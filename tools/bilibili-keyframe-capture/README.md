# B站关键帧抓取器（Chrome 扩展）

播放 B 站视频时**自动检测并抓取关键帧**（场景切换画面 / 定间隔抽样），按视频分会话保存在浏览器本地，
可浏览、回跳、导出 ZIP / GIF、下载原视频。

> Chrome / Edge（Manifest V3，需要 Chrome 116+），完全在本地运行，不联网上传任何数据。

---

## 一、安装（开发者模式加载）

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
2. 右上角打开 **开发者模式**。
3. 点 **加载已解压的扩展程序**，选择本目录：`tools/bilibili-keyframe-capture`。
4. 打开任意 B 站视频页并播放，**页面左侧**会出现垂直排列的「关键帧抓取」悬浮面板。

首次安装会自动打开一次 B 站首页；如果面板没出现，刷新一下视频页面即可。

> **默认是暂停的**：进入页面后**不会自动抓取**（默认模式为「仅手动」），需要时自己点
> 面板上的「抓取当前帧 / 开始自动抓取 / 🎬 播放并抓帧」。这样不会在后台默默消耗 CPU 与磁盘。
> 老版本升级上来、模式仍是「自动·关键帧」的，会在首次加载时一次性迁移成「仅手动」；
> 主动选过的「逐帧 / 定间隔」模式不受影响。

面板说明：固定在页面左侧不会挤动播放器、也不会被 B 站下方的「笔记 / 视频详情」等浮动组件遮挡；
按住顶部把手可以拖到任意位置（位置会被记住），点 `‹` 收起成细竖条，弹窗里可「重置位置」。

## 二、使用

| 操作 | 位置 |
| --- | --- |
| 抓取当前画面 | 左侧面板「抓取当前帧」，或快捷键 **Alt+K** |
| 开始 / 暂停自动抓取 | 左侧面板的「开始 / 暂停自动抓取」（默认暂停，状态会记住） |
| 播放并抓帧（整片自动扫一遍） | 左侧面板「🎬 播放并抓帧」，或扩展弹窗的同名按钮 |
| 想每 100ms 都存一张 | 弹窗「抓取模式 → 逐帧抓取」，或「抓取风格 → 逐帧」预设 |
| 再抓一遍（补齐漏掉的采样点） | 面板「🔁 再抓一遍」，或弹窗同名按钮 |
| 看判定次数 / 命中率 | 面板帧数下方、弹窗状态行，或面板「诊断」 |
| 浏览全部关键帧 | 左侧面板「图库」，或扩展图标弹窗里的「打开图库」 |
| 移动 / 收起面板 | 拖面板顶部把手移动；点 `‹` 收起成细竖条 |
| 回跳到某个关键帧的时间点 | 图库缩略图左下角的时间码 |
| 多选 / 导出 / 删除 | 图库工具栏（全选、导出 ZIP、导出 GIF、存到文件夹、清理重复帧、清空本会话、删除会话） |
| 连环播放预览 | 图库工具栏「单图集播放」（可调速度、可一键导出 GIF） |
| 下载原视频 | 图库或弹窗的「下载原视频 / 下载视频」 |
| 回到原始播放页 | 图库工具栏「回到原播放页」（在新标签页打开该会话对应的视频页）；弹窗会话列表每条也有「原页」按钮 |
| 调参数 | 扩展图标弹窗（灵敏度、间隔、格式、上限、去重、扫描参数…） |

快捷键可在 `chrome://extensions/shortcuts` 里改成自己喜欢的组合。

**图库里的每张缩略图**：左上角复选框（多选批量导出）、左下角时间码（点击回跳）、
右上角 `Δ` 变化量、底部一行的文件名 +「下载 / 删除」。

> 工具栏左侧的「已选 N」和「预览 i / N」是**两个独立计数**：前者是你勾选的数量，
> 后者是大图预览里的位置。它们各占一个元素，不会互相覆盖。

**回到原播放页**：每帧都记录了抓取时的页面地址（会话里也存了一份）。点「回到原播放页」
会在**新标签页**打开该地址 —— 走的是正常页面加载，所以 B 站 SPA 会重新初始化并正常播放，
而不是只改地址栏（那样播放器可能没反应）。

## 二·五、播放并抓帧（自动扫描整个视频）

点面板上的 **🎬 播放并抓帧**：扩展会让隐藏的取帧用 video 以设定的倍速（默认 4×）
从片头播到片尾，按间隔采样判定关键帧并保存；面板与弹窗会实时显示
「当前时间 / 总时长 / 进度 % / 已抓帧数 / 预计剩余」，再点一次即可随时中止。

- **与实时监听的区别**：实时监听只在你实际观看时抓取；「播放并抓帧」会把整段视频过一遍，
  适合打开一个视频就先产出全套分镜图，不必真的看完。
- **耗时估算**：大致为 `时长 ÷ 倍速`（4× 时 1 小时视频约 15 分钟）加取帧开销。
- **采样间隔**：默认 1 秒。> 0.95 秒时走逐点定位（最准）；调到 0.2~0.4 秒会切换为
  倍速连续播放采样，更快，但可能漏掉极短的镜头。
- **扫描期间**：默认暂停你正在看的播放器（省带宽、省 CPU），扫描结束后自动恢复；
  扫描结束默认自动打开图库查看结果。
- **上限**：按「单会话上限」的剩余额度抓取，抓满即停，不会超。
- **中止**：随时再点一次按钮（或弹窗里的「停止抓帧」），已抓到的帧都会保留。

## 三、关键帧是怎么判定的

对每一帧（**默认每 100 毫秒**采样一次，配合 `requestVideoFrameCallback`，最多每帧判定一次）做两件低成本的事：

1. **dHash 感知哈希**：把画面缩成 11×10 灰度图，比较相邻像素得到 100 bit 指纹；
   与上一张**已保存**的关键帧比较汉明距离，大于阈值（默认 12%）说明构图变了。
2. **灰度平均绝对差（MAD）**：把画面缩成 16×16，与上一张关键帧逐像素求平均差，
   大于阈值（默认 10%）说明明暗/内容整体变了。

两者**任一**明显变化、且综合变化量超过阈值时，判定为场景切换并保存该帧。
纯黑、纯色画面（例如加载中、黑场过渡）会被直接跳过。

- 阈值可以在弹窗里调：**越小越灵敏**（抓得更多）。
- **「采样间隔」≠「保存张数」**：100ms 是*判定*节奏，关键帧模式只保存「画面明显变化」的帧。
  5 秒视频按 100ms 会判定约 50 次，但可能只命中几次场景切换 —— 这是设计如此，不是丢帧。
  面板与弹窗都会显示「判定 N 次 · 命中 X%」，可直接看到这个比例。
- **想让每 100ms 都存一张**：把抓取模式切到 **逐帧抓取**（弹窗里还有一键预设
  「逐帧：100ms，5 秒 ≈ 50 张」）。该模式按间隔无条件保存，只会挡掉「连续两次采样落在同一帧」
  的情况（同一画面存两份没有意义）。
- 采样本身极便宜（缩成 11×10 灰度图算哈希），真正耗时的是命中后的编码写入；
  同一时刻只处理一帧，不会因为间隔小而发生堆积。

### 重复帧的处理

- **相似度去重**（弹窗可调，默认 2.5%）：与**上一张已保存的帧**差异小于该值就直接跳过，
  避免同一场景被连续采样存成好几张几乎一样的图。
- **指纹相同不重复入库**：同一会话内 dHash 指纹完全相同的帧不会被写入第二次（走 `hashes` 索引，O(1)）。
- **自动删除重复帧**（弹窗开关，**默认开启**）：一批画面写完后（防抖 4 秒）后台会扫一遍，
  把同一指纹的旧帧删掉，每个画面只留最后一张。
- **手动清理**：图库工具栏的「清理重复帧」按钮，可对已有会话立刻去重。
- 图库里若某张缩略图带红色 **重复** 标记，说明它的指纹与前面某张相同。

### 想抓更多？多播几遍（面板「🔁 再抓一遍」）

采样是异步推进的：某次**编码写入超过采样间隔**时，那一段的采样点会被跳过，
而这些空洞在每次播放里**位置固定** —— 所以直接重播往往捞不到新东西。
面板上的 **🔁 再抓一遍** 会：回到片头重播、重置判定基准、累加遍数（面板显示「第 2 遍」），
让新一遍从不同相位覆盖上一遍漏掉的画面；**相同画面不会重复保存**，所以多播几遍只增不减。
（看视频自然循环也会被识别为下一遍。）

> 说明：多播能补的是「因编码耗时被跳过的采样点」，不是凭空变出新的画面内容；
> 如果确实想要每个采样点都落图，直接用**逐帧抓取**模式更省事。

### 抓取风格预设（弹窗一键套用）

| 预设 | 模式 | 间隔 | 灵敏度 | 上限 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 逐帧：100ms，5 秒 ≈ 50 张 | 逐帧抓取 | 100ms | 12 | 5000 | 要「每个采样点都留一张」的素材采集 |
| 平衡：200ms + 灵敏度 8 | 关键帧 | 200ms | 8 | 1000 | 日常使用，抓得比默认多一些 |
| 仅场景切换：100ms + 灵敏度 14 | 关键帧 | 100ms | 14 | 300 | 只要分镜/场景切换图 |

### 「暂停自动抓取」为什么能记住

- 点暂停 → 把 `mode` 写成 `off`（**持久化**），并记住暂停前用的模式（`lastActiveMode`）；
- 点开始 → 恢复到记住的那个模式（关键帧 / 逐帧 / 定间隔），不会被强制改成关键帧模式；
- 面板与弹窗两条路径都走同样的持久化逻辑。

> 踩过的坑：默认模式就是 `off`，如果判断条件写成「`running` 为假 **或** `mode === 'off'` 就当作暂停」，
> 点「开始」会走进暂停分支、什么都不做，表现为**按钮完全没反应**。
> 正确做法是只看 `controller.running`。该回归点已由 `smoke.mjs` 的 [3] 组用例覆盖。

## 四、取帧原理（以及为什么这么做）

B 站视频像素来自 `*.bilivideo.com` 等 CDN。**CDN 不接受带 `Origin` 的匿名请求**，
所以「给隐藏 video 加 `crossOrigin="anonymous"` 再读像素」这种常见做法在本站连元数据都加载不了
（就是「无法通过 CORS 读取视频像素：加载视频元数据失败」这个报错的来源）。

扩展改成**自己取数据**：内容脚本的 `fetch` 受扩展的 host_permissions 授权，不受页面 CORS 限制，
拿到数据再喂给隐藏 video，于是画布天然干净。按顺序三级降级：

| 方式 | 做法 | 什么时候用 |
| --- | --- | --- |
| `direct` | 隐藏 video 直接 `crossOrigin` 加载原地址 | 最快、不额外占内存；CDN 允许时就用它 |
| `blob` | `fetch` 把视频抓成 blob 再挂给 video，边下边显示进度 | 直连失败；上限 1.5 GB |
| `mse` | `fetch` + `MediaSource`：先取 512 KB 解析 fMP4 结构，之后每 ~4 MB 追加一段，边下边取帧；缓冲超 96 MB 暂停下载、丢弃播放点 30 秒前的旧数据 | 超长视频 / 直连与整段下载都不可行时 |

**地址从哪来**（新版播放器经常把 `currentSrc` 设成 `blob:`，光靠它取不到帧）：

1. `window.__playinfo__` 里的 DASH 视频流（≤1080p 优先，纯视频轨）——需要注入页面主世界才读得到；
2. 播放器实例（`window.player.getPlayInfo()`）里的地址；
3. **后台用 `chrome.webRequest` 观察播放器实际请求的 CDN 地址**（观察模式，不需要 `debugger`
   权限、不弹调试横幅）。只收**真正的媒体流**：先按 MIME（`video/*`、`audio/*`）判定，
   再用扩展名 / `upgcxcode` 路径特征过滤，**明确排除 `i0.hdslb.com/bfs/...` 这类封面图与静态资源**；
4. `video.currentSrc` 兜底（若为 `blob:` 会明确告诉你这条走不通）。

候选拿到后还会做一次轻量探针（读前 64 KB）：识别容器（AVIF 图片 / HTML 错误页 → 直接判为「非媒体」
并跳过）、区分视频轨（`avc1`/`hvc1`/`av01`）与音轨（`mp4a`/`opus`），**视频轨优先**。

**切换视频时会重建取帧源**：SPA 换视频 / 换分P 时 URL 变了但 `video.currentSrc` 可能还是旧的，
所以扩展同时监听 URL 与播放器地址，一变就作废记住的地址、重建取帧源，
并用**会话世代号**丢弃切换瞬间还在途中的抓帧结果（不会写进新会话）。

**已知限制**：付费/DRM 内容、直播（MSE `blob:` 地址）仍无法取帧，面板会给出具体原因。

## 五、下载 / 导出的文件去哪了

| 动作 | 落到哪里 |
| --- | --- |
| 下载原视频 | **浏览器默认下载目录**（Windows 一般是 `C:\Users\<你>\Downloads`），文件名形如 `视频标题_原视频_20250101-120000.mp4`。弹窗里有 **打开下载目录** 按钮可直接定位 |
| 导出 ZIP / GIF / 单帧 | 同上，走浏览器下载（文件名会在下载栏显示） |
| 存到文件夹 | 你**自己选择**的目录（Chrome 文件系统访问 API），扩展会在其中新建「视频名 + 时间戳」子文件夹 |

> 「下载原视频」的声音问题：B 站 DASH 把音视频分成两条流。扩展优先下载**音视频合一的整段文件**
> （`__playinfo__.durl`）；只有视频轨可用时会下载视频轨，并在提示里明确标注「仅视频轨、无声音」。

## 六、数据存在哪里

- 存储介质：扩展自己的 IndexedDB（`bilibili-keyframe-capture`），内含
  `sessions`（会话）、`frames`（关键帧，含全尺寸 blob）与 `hashes`（画面指纹索引）三个对象仓库。
- 不随 B 站页面刷新、清缓存、关标签页而丢失；**卸载扩展会一并删除**。
- 已申请 `unlimitedStorage` 权限，不受网页 5MB 配额限制；弹窗顶部会显示已占用空间。
- 卸载前请先在图库里导出需要保留的帧。

导出 ZIP 的结构：

```
<title>_<时间戳>.zip
├── frames/
│   ├── 001_00-00-01-200.jpg
│   ├── 002_00-00-05-640.jpg
│   └── ...
├── index.csv        # 文件名、时间点(秒/时码)、分辨率、字节数、第几遍、变化量
└── metadata.json    # 视频标题、UP 主、BV 号、时长、每帧时间点与检测指标
```

## 八、开发与自测

```powershell
# 纯逻辑自测：关键帧算法、时间格式化、ZIP 结构（真实解压比对）、扫描循环、去重计划、GIF 编码
node tools/bilibili-keyframe-capture/tools/selftest.mjs

# 运行时冒烟测试：后台 Service Worker + 内容脚本真实加载一遍，
# 校验消息路由、帧写入/去重、面板按钮绑定、开始暂停链路
node tools/bilibili-keyframe-capture/tools/smoke.mjs

# 重新生成图标
powershell -ExecutionPolicy Bypass -File tools/bilibili-keyframe-capture/tools/generate_icons.ps1
```

> `node --check` 只验语法。脚本在**加载期**抛异常时语法检查完全看不出来，
> 表现为「按钮点了没反应」（监听器根本没注册）—— 这类问题由 `smoke.mjs` 覆盖。
> 另外面板上的按钮如果抛错，会直接在面板上显示错误并可展开看堆栈，不再静默失败。

改完代码后在 `chrome://extensions/` 点该扩展的 **刷新** 按钮，然后刷新 B 站页面即可。
调试建议：扩展的 **服务工作进程**（`chrome://extensions/` → 详情 → Service Worker）看后台日志；
B 站页面的 DevTools Console 会打印内容脚本的告警（前缀 `[关键帧抓取]`）。

## 九、常见问题

| 现象 | 处理 |
| --- | --- |
| 面板没出现 | 刷新 B 站页面；或在弹窗里勾选「在页面左侧显示悬浮面板」 |
| 面板挡住内容 / 想换位置 | 拖面板顶部把手移动，点 `‹` 收起成细竖条；弹窗「重置位置」恢复默认 |
| 面板显示「下载视频 … / …」 | 正常流程：CDN 不允许匿名直连，扩展正在把视频取回来（会缓存，通常很快） |
| 抓帧失败 | 点面板底部 **诊断** 看完整原因（面板太窄会截断），再点 **复制诊断** 可直接粘贴反馈 |
| 诊断说地址是 `blob:` | 点面板上的 **重新获取视频地址**；扩展会去读播放器实际请求的 CDN 地址并切换过去。若提示没观察到请求，先在页面里点一下播放 |
| 采样 50 次只存了几张 | 关键帧模式只保存画面明显变化；想要每张都存请切「逐帧抓取」，或把相似度去重调小 |
| 抓到的图有重复 | 弹窗确认「自动删除重复帧」已开启；对已有会话点图库「清理重复帧」 |
| 扫描按钮提示需要先点击页面 | 浏览器要求先有用户交互才允许播放媒体，点一下页面再试 |
| 扫描很慢 | 提高「扫描倍速」（8×/16×）或放大「采样间隔」；长视频本就耗时 |
| 扫描漏掉短镜头 | 把「采样间隔」降到 0.2~0.4 秒，并调低关键帧灵敏度 |
| 下载的视频没有声音 | 该视频只有 DASH 视频轨可用；扩展会优先选音视频合一的整段文件，找不到时会在提示里注明 |
| 提示所有地址都失败 | 常见原因：视频是 `blob:`（直播 / DRM）、HTTP 403 防盗链（先点播放让播放器正常加载）、编码不被系统支持。诊断文本里会写明是哪种 |

## 十、隐私与权限

扩展只在 `*.bilibili.com` 页面上运行，收集的信息（视频标题、BV 号、时间点、截图）
全部保存在本机浏览器存储中，不做任何网络上传；仅在你点击导出时才写入你选择的文件。

权限说明：

- `webRequest`：**观察模式**，只读、不拦截、不改写请求，用于看播放器请求了哪些 CDN 地址；
- `scripting`：在主世界读一次 `__playinfo__`；
- `downloads`：导出 ZIP / GIF 与下载原视频；
- `storage` + `unlimitedStorage`：本地保存关键帧数据（不受网页 5MB 配额限制）。
