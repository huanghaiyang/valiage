## 0. 先记住四条铁律 ✓

| # | 铁律 | 原因（都是实测踩出来的 ✓） |
|---|---|---|
| **1** | **薄片面不参与减面** ✓ | 薄片每块只有 1~4 个三角 ✓ → 边塌陷**数学上无效** ✗，而且会把叶子**砍掉一块** ✗ |

## 1. 薄片（thin-shell）的识别 ✓

### 1.1 判据（纯几何 ✓ 与模型语义无关 ✓）

```
薄片面 ⇔ 三角 ≥ 64  且  顶点/三角 ≥ 1.5  且  连通块 ≥ 16
```
- **顶点/三角 ≥ 1.5** ✓：完全独立面为 3.0 ✓；紧密共享网格约 0.5 ✗
- **连通块** = 用并查集按"共享顶点"把三角分组后的块数 ✓（`_tri_groups()` ✓）
- 该判据**不针对树** ✓：树叶 ✓ 草丛 ✓ 花瓣 ✓ 栅栏铁艺 ✓ 布料 ✓ 绳链 ✓ 羽毛卡片 ✓ 都会命中 ✓

### 1.2 本树实测（`tree_small_02_4k.blend` → `tree_small_02_LOD1`）

```
surface 0  branches   94,814 三角   V/T 0.66   751 块    实心 ✓ → 可减面
surface 1  leaves    386,574 三角   V/T 1.58   175,899 块 薄片 ✓ → 跳过减面，可抽稀
surface 2  trunk      14,145 三角   V/T 0.60   81 块     实心 ✓ → 可减面
────────────────────────────────────────────────
合计                 495,533 三角（叶子占 78% ✗ 减面动不了它 ✓）
叶子成分：1面×56,703 ｜ 2面×61,159 ｜ 3面×30,685 ｜ 4面×23,319 ｜ 5~7面×4,033
        平均 2.20 三角/块 ｜ 最大 7 三角  ← 即"一片叶子 2~3 个三角" ✓
```

### 1.3 推论

- 减面 ratio 对叶子**无效** ✗ → `0.05` 与 `0.5` 视觉差别很小 ✓（只有 22% 的枝干在掉 ✓）
- 降叶子面数只有三条路 ✓：**整片丢（抽稀）** ✓ ／ **card 化** ✓ ／ **Impostor** ✓

## 2. 策略一：减面**跳过**薄片面（`_solid_only()` ✓）

```
_decimate_mesh(src, ratio, mi)
  ① _solid_only(src) → { mesh: 只含实心面的网格, solid_idx, thin_idx }
     · 全是薄片 → 直接返回 ✓（省掉一次外部调用 ✗ 不浪费时间 ✓）
  ② 把"只含实心面"的网格借**真实节点 mi** 写临时 glb ✓
  ③ python tools/glb_simplify.py --ratio R ✓
  ④ 读回 → 只取网格 ✓
  ⑤ 材质按 **solid_idx 序号表**回填 ✓（拆分后序号不再一一对应 ✗）
  ⑥ ★ 把**原始薄片面原样接回** ✓（形状 100% 不变 ✓ 叶子再也不会被割 ✓✓）
```
**要点** ✓
- 接回薄片时材质要取**预览副本**的 ✓（见 §5 铁律 3 ✓）
- 任何一步失败 → 返回原网格 ✓ + 明确 warning ✓（导出永远安全 ✓）

## 3. 策略二：薄片**抽稀**（`_thin_leaf_mesh(src, keep)` ✓）

```
① 逐 surface 算 V/T + 连通块 ✓（先做便宜判据 ✓ 明显实心就不跑并查集 ✗）
② 非薄片 → 原样搬运 ✓（材质一并复制 ✓）
③ 薄片 → 逐**块**以概率 keep 保留 ✓（整片保留或整片丢弃 ✓ 绝不逐个三角丢 ✗ 那样会撕裂叶子 ✓）
④ 重建索引 ✓ + ★ **顶点重映射压缩** ✓（只保留用到的顶点 ✓ 否则体积不降 ✗）
   · 法线 / 切线 / UV / 顶点色 同步压缩 ✓
⑤ 固定随机种子 seed=20240607 ✓ → 每次导出结果**一致**（可复现 ✓）
```
**关键坑（今天踩过 ✓）**
| 坑 | 正确做法 |
|---|---|
| `ARRAY_TANGENT` 被当成 `PackedVector4Array` ✗ | Godot 里它是 **`PackedFloat32Array`** ✓（每顶点 4 个 float ✓） |
| 反复点"抽稀"越抽越稀 ✗ | 每次从**原始网格**重算 ✓（不是在上次结果上再抽 ✓） |
| 抽稀结果没 UV ✗ | 重建时**必须**写回 `ARRAY_TEX_UV` / `ARRAY_COLOR` / `ARRAY_INDEX` ✓ |

**实测** ✓：`386,574 → 76,827 三角`（keep=0.2 ✓）、`111,621 → 22,145 片` ✓

## 5. ★★★ 三条"输入来源"原则（今天最大的坑 ✓）

| 用途 | 必须用 | **不能**用 | 否则 |
|---|---|---|---|
| **几何输入**（抽稀/减面） | **真·原始网格** ✓ = `mi.get_meta("blend_orig_mesh")` ✓ | 预览当前 `mi.mesh` ✗ | **试看污染导出** ✓（把处理结果当原始 ✓） |
| **材质（预览显示）** | **预览那份带贴图副本** ✓（`_tr_prev` / `mi.mesh` ✓） | 原始 blend 网格的材质 ✗ | **贴图没了** ✓（原始材质无 `resource_path`/贴图链接 ✗） |
| **材质（导出落盘）** | `_build_material()` **重建** ✓（材质名 + 贴图名字回链 ✓ → `.tres` 引用贴图 ✓） | 预览的内存材质 ✗ | `.tres` 无路径 → 白模 ✗ |

### 5.1 试看污染事故（真实案例 ✓）

```
预览窗口里 mi.mesh 会被替换成"带贴图的替身 / 抽稀结果 / 减面结果" ✗
旧代码却直接记：originals[id] = mi.mesh ✗
  → "处理结果"被当成"原始输入" ✓ → 一路污染到导出 ✗
  → 典型症状：导出材质变成 `_blend_mat__unnamed__.tres` ✗ + 白模 ✓
修复：originals[id] = mi.get_meta("blend_orig_mesh", mi.mesh) ✓
另加保险：材质回填时**绝不留 null** ✓（null → `_mat_key` 得 `__none__` → `__unnamed__` ✗）
        取不到就退回"原网格第一个非空材质" ✓ + 打警告 ✓
```

### 5.2 缓存开关 ✓

```gdscript
static var use_trial_cache := false   # ★ 默认关闭 ✓
# 关闭 = 导出走**干净独立**的完整路径 ✓（今天最终确认"导出正确"的配置 ✓）
# 打开 = 复用「试看减面」的结果 ✓（导出瞬间完成 ✓，但要求试看结果与真实结果一致 ✓）
```
> 结论 ✓：**先把导出做对 ✓，再谈"瞬间完成" ✓**。开启前必须校验缓存网格的 surface 数/材质是否与直接导出一致 ✓。
