# 落叶与落花 — 技术文档

> 代码：`scripts/vfx/falling_leaves.gd` ｜ 着色器：`assets/shaders/falling_leaves.gdshader`
> 场景接入：`scenes/树/大樱花树/big_sakura_tree.tscn`（`FastTree/FallingLeaves`）
> 风场接入：`scripts/wind.gd`（`_register` 白名单 + `_write_mats` 每帧写入）
> 移植来源：`D:\sgames\fast-tree\src\core\fallingLeaves.js`（下文简称"源实现"）

## 1. 目标与拆解

用户要求分两步：

1. **参考 fast-tree 实现落叶效果** —— 与树同一套风场、真实叶片卡片、整层合批；
2. **做判断：有树叶就落树叶，有花朵就落花朵，两者都有就全落，并且要求能够分开配置。**

拆成 4 个部件：

| 部件 | 位置 | 职责 |
| --- | --- | --- |
| 卡片着色器 | `falling_leaves.gdshader` | 生命循环 / 翻滚 / 下落 / 受风 / 贴图裁形，全部在顶点 + 片元里算 |
| 驱动脚本 | `falling_leaves.gd` | 构建期撒出生点、生成网格与材质；运行时只做可见性校准 |
| 场景节点 | `big_sakura_tree.tscn` | `FastTree` 下新增 `MeshInstance3D`（`FallingLeaves`），不手填网格 |
| 风场接入 | `wind.gd` | 把落叶材质纳入 `_mats_tree`，与树共用同一份风向/阵风/风力 |

**设计取舍：脚本不是 `@tool`。** 编辑器预览里不生成任何飘落卡片，避免"打开场景就多出一层运行时特效"；
所有构建都发生在 `_ready()`，不影响现有编辑器预览与场景文件内容。

## 2. 与源实现的对应关系

| 源实现（`fallingLeaves.js`） | 本实现 | 说明 |
| --- | --- | --- |
| `aLeafSeed = (phase, speedScale, sizeScale, spinDir)` | `CUSTOM0`（`ARRAY_CUSTOM0`，RGBA_FLOAT） | 每片卡片的随机种子 |
| `uFallHeight`（整树高度） | `CUSTOM1.x = fall_dist`（逐片） | 见 §4.2 的适配差异 |
| `t = fract(uTime * uFallSpeed * speedScale * 0.35 + phase)` | `t = fract(TIME * fall_speed * speed_scale * 0.35 + phase)` | 生命循环，每片错开 |
| `R = rotY(spin) * rotX(tumble) * rotZ(...)` | 同左 | 自旋 + 翻滚 + 侧倾 |
| `p.y -= t * uFallHeight` | `p.y -= t * fall_dist` | 下落 |
| `fade = 1 - smoothstep(0.85, 1.0, t)` | 同左 | 落地前 15% 生命淡出 |
| `p.xz += windDir * along * (3 + 14t)` | 同左 | 越到后期被吹得越远 |
| `sin/cos(ang) * uSwirl * ...` | 同左 | 空中打旋（无风也飘一点） |
| `uHalf` = 贴图宽高比推卡片半宽 | `card_half`（逐材质，按各来源贴图算） | `half.x = 0.5 * clamp(aspect, 0.35, 1.6)` |
| `uHasMap < 0.5` 椭圆裁形兜底 | 同左 | 没贴图时不会出现一堆方块 |
| 风场 uniform 与树共用同一批对象 | 风场 uniform 与树共用同一份（`wind.gd` 每帧写） | 风一变，落叶与树梢同步同向 |

## 3. 卡片数据布局（关键约束）

每片叶/花 = **4 顶点 / 2 三角**，一个来源只占 **1 个 surface（1 个 draw call）**。

```
POSITION （ARRAY_VERTEX）  = 出生点（同一片卡片的 4 个顶点写同一个值）
UV       （ARRAY_TEX_UV）  = (0,0) (1,0) (1,1) (0,1)
CUSTOM0  （ARRAY_CUSTOM0） = (phase, speedScale, sizeScale, spinDir)
CUSTOM1  （ARRAY_CUSTOM1） = (fallDist, 0, 0, 0)
INDEX                       = (0,1,2) (0,2,3)
```

为什么 POSITION 存出生点而不是四个角：

* 一片卡片只需要 **1 个位置**就能携带完整运动状态，顶点数据量减半（源实现同一思路）；
* 卡片的真实形状由 UV 在顶点着色器里展开：`local = (UV - 0.5) * 2 * card_half * size_scale * size`，
  再由 `R` 旋转后加到出生点上 —— CPU 完全不用逐帧算任何顶点。

**必须显式声明自定义属性格式**（踩过的坑）：

```gdscript
const CUSTOM_FLAGS := (Mesh.ARRAY_CUSTOM_RGBA_FLOAT << Mesh.ARRAY_FORMAT_CUSTOM0_SHIFT) \
        | (Mesh.ARRAY_CUSTOM_RGBA_FLOAT << Mesh.ARRAY_FORMAT_CUSTOM1_SHIFT)
am.add_surface_from_arrays(Mesh.PRIMITIVE_TRIANGLES, arrays, [], {}, CUSTOM_FLAGS)
```

不写 flags 时 `add_surface_from_arrays` 会按默认 `RGBA8_UNORM` 去要 `PackedByteArray`，
结果是 `Invalid array format for surface` → 没有 surface → 整层不显示。
（同样的写法参考 `scripts/world/canopy_chunk_cull.gd` 的 `_chunk_mesh()`。）

渲染设置：`blend_mix, depth_draw_never, cull_disabled, unshaded`；节点侧 `cast_shadow = OFF`、
`gi_mode = DISABLED`（80~140 张半透明卡片不参与阴影与 GI）。

## 4. 出生点采样

### 4.1 面积加权 + 重心采样

遍历来源网格（`Leaves` / `Flowers`）的所有三角形，按**三角形面积**建累积分布（CDF），
每片卡片随机取一个三角形，再用重心坐标取点：

```gdscript
var r1 := sqrt(_rng.randf())          # sqrt 保证在三角形内均匀分布
var r2 := _rng.randf()
p = a * (1 - r1) + b * (r1 * (1 - r2)) + c * (r1 * r2)
```

等价于源实现的 `sampleEmitPositions`（粒子与落叶共用同一套树冠采样）：**花/叶密的地方落得也多**。

采样种子固定为 `RNG_SEED = 20261026`，因此每次进游戏落叶分布一致（便于复现问题）。

### 4.2 逐片 `fall_dist`（相对源实现的刻意差异）

源实现用**整树高度**当所有叶片的下落距离。但本项目树冠是"扁平大冠"，低处的叶片出生在 y≈4（模型单位），
用整树高度 27 会让它在地下走完大半生命 —— **地面上方根本看不到它**。
所以构建时直接写入 `fall_dist = max(3.0, spawn.y - 地面)`，保证 `t = 1` 时正好落到地面、淡出。

### 4.3 树冠分块兼容

`scripts/world/canopy_chunk_cull.gd` 会把 `Leaves` / `Flowers` 切成 8 块：
原节点 `mesh` 置空、块作为子节点接管渲染。脚本自动兼容两条路径：

* `src.mesh != null` → 直接采样原网格；
* `src.mesh == null` → 遍历 `src` 的子 `MeshInstance3D` 块并拼接几何。

块的顶点坐标与原来的局部空间一致（分块只裁三角形、不改变换），所以拼接后直接可用。
`_ready()` 顺序上 `FallingLeaves` 是 `FastTree` 的子节点，先于根下的 `CanopyCull` 执行，
正常情况下走的是"原网格"路径。

## 5. 两个来源独立配置

一个来源 = **一个 surface + 一份材质 + 一组独立参数**。两个来源互不影响：

| 组 | 参数 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 通用 | `enabled` | `true` | 总开关 |
| 通用 | `spin_speed` / `swirl` / `stagger` | `1.2` / `1.0` / `0.6` | 自旋与打旋 |
| 通用 | `opacity` / `alpha_test` | `1.0` / `0.35` | 不透明度、贴图裁形阈值 |
| 树叶 | `leaves_enabled` | `true` | 关掉即不落树叶 |
| 树叶 | `leaves_path` | `../Leaves` | 相对本节点的路径 |
| 树叶 | `leaves_count` | `80` | 源实现默认数量 |
| 树叶 | `leaves_texture` | 空 | 留空自动取树叶材质的 `albedo_tex` |
| 树叶 | `leaves_size_scale` | `0.9` | ≈ 0.26 米（树高 27 单位 ≈ 8 米） |
| 树叶 | `leaves_fall_speed` / `leaves_wind_follow` | `1.0` / `1.0` | 下落速度、跟随风力 |
| 花朵 | `flowers_enabled` | `true` | 关掉即不落花 |
| 花朵 | `flowers_path` | `../Flowers` | 相对本节点的路径 |
| 花朵 | `flowers_count` | `60` | 花瓣比树叶少一些 |
| 花朵 | `flowers_texture` | 空 | 留空自动取花朵材质的 `albedo_tex` |
| 花朵 | `flowers_size_scale` | `0.8` | 花瓣卡片略小 |
| 花朵 | `flowers_fall_speed` / `flowers_wind_follow` | `0.85` / `1.6` | 花瓣更轻：落得慢、飘得远 |

"做判断"体现在构建期：某个来源**开关关闭**、**场景里没有该节点**、或**几何为空**时，
该来源直接被跳过并打印原因，另一个来源照常工作：

```
[落叶] 构建完成：140 片（树叶 80 片 ｜ 花朵 60 片）
[落叶] 构建完成：80 片（树叶 80 片 ｜ 花朵 关闭）
[落叶] 构建完成：120 片（树叶 关闭 ｜ 花朵 120 片）
```

每个来源的贴图独立解析：材质 `leaf_tex = albedo_tex`，`card_half` 按该贴图宽高比计算
（树叶 `大樱花树_leaf_diff.png` 141×204 → `half.x ≈ 0.346`；花朵按 `大樱花树_flower_diff.png` 的宽高比）。
因为卡片形状来自 UV 展开，同一张贴图在"树上"和"飘落"时观感一致。

## 6. 风场接入

### 6.1 为什么必须改 `wind.gd`

`scripts/wind.gd` 每帧只给**白名单里的材质**写风参数（判定依据是 shader 资源路径的**子串**）。
落叶材质如果不登记，就只有 shader 里的默认风（方向恒定 `(1,0)`、风力恒定 `0.06`），
天气一变风向，落叶会和树梢**反向飘**。

```gdscript
var is_tree := path.contains("tree_leaves_burn") or path.contains("tree_burn_keep") \
        or path.contains("falling_leaves")
```

登记进 `_mats_tree` 后，落叶与树拿到**完全相同的一份**：

| uniform | 含义 | 写入方 |
| --- | --- | --- |
| `wind_direction` | 水平风向 | `wind.gd` 每帧 |
| `wind_gust` | 阵风 0..1 | `wind.gd` 每帧 |
| `wind_speed` | 相位推进速度 | `wind.gd` 每帧 |
| `wind_force` | 树梢顺风偏移量级（**米**） | `wind.gd` 每帧（`tree_force_min + strength × per_wind`） |
| `wind_gust_speed` / `wind_bias` | 阵风脉动速度 / 顺风静态偏置 | `wind.gd` 每帧 |
| `wind_enabled` | 材质级总开关 | shader 默认 `true`（`wind.gd` 不写） |

### 6.2 单位换算

本项目风系统约定 `wind_force` 是"米"量级，而源实现用的是 0..1 相对风强。着色器里：

```glsl
float along = wind_enabled ? (wind_force * 3.0 * wind_follow * (0.55 * gust + wind_bias * 0.45)) : 0.0;
p.x += wd.x * along * (3.0 + 14.0 * t);
```

`×3.0` 是米 → 相对量的换算系数；`wind_follow` 是**逐来源**的倍率（花瓣默认 1.6，更轻、飘得更远）。
注意位移是在**模型空间**里叠加的，所以落叶与树冠（同样在模型空间算风摆）缩放一致。

### 6.3 登记时机

落叶材质是在 `_ready()` 里**运行时新建**的，`wind.gd` 的 `_scan()` 每 `scan_interval = 0.5` 秒重扫一次
（`_take_from_mesh` 会遍历 mesh 的每一个 surface 材质），因此最迟 0.5 秒后就被登记。
冒烟日志可见 `树` 的材质数由 3 涨到 5（树皮 + 叶 + 花 + 落叶 + 落花）。

## 7. 与燃烧 / 重生的配合

### 7.1 逐来源隐藏

`_process()` 每 0.25 秒（`CHECK_INTERVAL`）逐来源判断，把对应材质的 `opacity` 写成 0 或原值：

```gdscript
mat.set_shader_parameter("opacity", _base_opacity[i] if on else 0.0)
```

判定条件（`_is_foliage_visible`）：

* 该来源材质 `burn > 0.05`（正在烧）或 `ash > 0.05`（已烧成灰）→ 隐藏；
* `growth_enabled == true` 且 `growth < 0.9`（正在重生）→ 隐藏。

**树叶烧完只停落叶，花朵还在就继续落花** —— 两个来源各判各的。

### 7.2 为什么必须动态解析材质（踩坑）

`foliage_burn.gd` 点燃时会把 `material_override` 清掉，改成**逐面材质副本**（`duplicate()`），
`burn / ash / growth` 全部写在副本上。如果脚本在构建期缓存了原材质引用，读到的 `burn` 永远是 0
→ 烧树时落叶完全不停。

因此 `_find_foliage_material()` 每次都重新解析：`material_override` → 逐面覆盖材质 → 网格自带材质，
若原节点已分块则再看各块的材质。

### 7.3 树本体隐藏时自动跟随

`FallingLeaves` 是 `FastTree` 的子节点，`foliage_burn.gd` 在崩毁收尾执行
`_target.visible = false` 时，飘落卡片会**自动跟着隐藏**，不需要额外逻辑。

## 8. 性能与剔除

* **构建期一次性开销**：读取来源网格的三角形（大樱花树实测 `树叶三角形 20160 个`）、建 CDF、撒点、生成 `ArrayMesh`；
* **运行时零每帧开销**：运动全在顶点着色器，脚本只做 0.25 秒一次的可见性校准；
* **draw call**：每个来源 1 个（合计 2 个），与卡片数量无关；
* **`custom_aabb` 必须外扩**：顶点位移引擎看不见，剔除只用静态 AABB；
  脚本把 AABB 向水平方向各外扩 `CULL_PAD = 40` 模型单位、向下延伸到地面，
  否则"被风吹出包围盒"的卡片会在视角变化时突然消失/出现。

## 9. 已遇到的问题与排障

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `SHADER ERROR: No matching constructor found for: 'mat3'` + 整层不显示 | Godot 着色语言不支持 `mat3` 的 9 标量构造 | 旋转矩阵改为按列 `vec3` 拼：`mat3(vec3(...), vec3(...), vec3(...))` |
| 燃烧时落叶不停 | `material_override` 被换成材质副本，旧引用读到的 `burn` 恒为 0 | 每 0.25 秒重新解析当前材质（§7.2） |
| 落叶与树不同向 | 落叶材质没进 `wind.gd` 白名单 | `is_tree` 判定追加 `falling_leaves`（§6.1） |
| 靠近树时卡片"跟着视角闪烁" | 静态 AABB 看不见顶点位移 | 构建 `custom_aabb` 并外扩（§8） |

## 10. 调参指南

| 想要的效果 | 改哪个参数 |
| --- | --- |
| 落叶/花瓣太多或太少 | `leaves_count` / `flowers_count` |
| 卡片太大或太小 | `leaves_size_scale` / `flowers_size_scale`（模型单位，×0.294 ≈ 米） |
| 落得太快/太慢 | `leaves_fall_speed` / `flowers_fall_speed`（越小越慢） |
| 风一吹就飘很远 | `leaves_wind_follow` / `flowers_wind_follow` |
| 想换成别的贴图 | `leaves_texture` / `flowers_texture`（留空则跟随树材质） |
| 完全不要某一种 | `leaves_enabled = false` 或 `flowers_enabled = false` |
| 卡片翻转太疯 | `spin_speed`、`swirl`、`stagger` |
| 卡片太实/太透 | `opacity`、`alpha_test` |
