# 火焰推进 / 火焰灼烧 · 选点器技术文档

> 范围：`scripts/spells/spell_targeting.gd`（通用选点器：扇形 = 火焰推进、圆环 = 火焰灼烧）、
> `assets/shaders/spell_sector_screen.gdshader`（屏幕空间覆盖）、
> `scripts/spells/flame_advance.gd`（火焰推进的火焰摆放）、
> `scripts/spells/flame_scorch.gd`（火焰灼烧的贴地探测）、
> `scripts/spells/surface_overlay.gd`（物体表面绘制公共模块，与【物体探测】共用）。
>
> 本文记录**最终定稿方案**与**一路踩过的坑及结论**，供后续维护/扩展时不再重走弯路。

---

## 1. 需求与最终形态

| 需求（用户原话归纳） | 最终实现 |
|---|---|
| 扇形/圆环"扫到的地方就变白，不管是什么物体、不管多大，可以是整个物体也可以是一部分" | **屏幕空间覆盖**：相机前全屏面 + 深度纹理重建世界坐标，逐像素判定是否在范围内 |
| 圆环不要实心，只要外弧亮带 | `shape_mode = 1` + `screen_fill_strength_circle = 0.0`（只留外弧） |
| 鼠标指哪，圈就画哪；指到物体则落到其下方地面 | 斜射线命中 → **按层/组语义**判定"地面 / 物体"；判"物体"时再对**地形层**打一条垂直射线 |
| 火焰推进：火焰朝向扇形中轴、脚底不生成、也不要离太远 | 逐卡朝向 + 两遍实测留白（见 §5） |
| 火焰灼烧的贴地探测要用真实几何 | `_ray_down()` 两级探测：精确几何优先，必要时回退（见 §4.4） |

**核心结论（先说结果）**：静态范围指示器**不要用几何去逼近曲面**（射线贴合网格 / Decal / 逐物体挂材质都不行），
要**逐像素在世界空间判定**。这条结论是用十几轮失败换来的，见 §7。

## 2. 总体架构

```
[玩家按住选点]
   spell_caster._update_targeting()
        ├── configure(cfg)  → 模式：sector / disc
        ├── begin()         → set_process(true)   ← 选点器只在此时刻开始工作
        └── 每帧 _process()
              ├── sector 模式：_update_sector()    → 圆心=角色脚下，中轴指向鼠标
              └── disc   模式：_update_center_from_mouse() → 圆心=鼠标处地面
                        ↓（两种模式共用）
              _update_screen_pass()  → 写 uniform + 显示全屏面
                        ↓
   assets/shaders/spell_sector_screen.gdshader
        depth(DEPTH_TEXTURE) → INV_PROJECTION_MATRIX/INV_VIEW_MATRIX → 世界坐标
        → 世界 XZ 上判"是否在扇形/圆环内" → 加色上白
[松开/施放]
   end() → set_process(false) + 隐藏全屏面（必须显式隐藏，见 §7.6）
```

### 2.1 为什么是"屏幕空间覆盖"

判定对象是**像素**而不是"物体"：

* 地形、草、墓碑、17m 的碎块底座、被切到一半的物体全部天然正确；
* 边界就是扇形的两条边 + 外弧（逐像素，没有弦切割/裙边/阈值抖动）；
* 无几何、无回读、无逐面脚本 → **每帧零额外开销**（只有一次全屏面绘制）。

## 3. 关键文件与实现

### 3.1 `assets/shaders/spell_sector_screen.gdshader`

```glsl
render_mode unshaded, blend_add, depth_test_disabled, depth_draw_never,
             cull_disabled, shadows_disabled, ambient_light_disabled, fog_disabled;
uniform sampler2D depth_tex : hint_depth_texture;
uniform int   shape_mode;      // 0=扇形（两条边+外弧+内圈留白）  1=圆环（只有外弧）
uniform vec3  sector_center;   // 世界坐标（XZ 用，y 只参与高度下限）
uniform float axis;            // 扇形中轴角（atan2(z,x) 计）
uniform float half_angle;      // 半角
uniform float radius;          // 半径
uniform float inner_m;         // 内圈留白（扇形用；圆环传 0）
uniform float ground_y;        // ★ 高度下限锚点（见下）
uniform float floor_margin;    // 允许画到锚点以下多少米
uniform float fill_strength;   // 填充强度
uniform float edge_strength;   // 两条边线强度
uniform float rim_strength;    // 外弧亮带强度
```

要点：

1. **深度 → 世界坐标**用 Godot 内置矩阵：
   `INV_PROJECTION_MATRIX` * ndc → 除 w → `INV_VIEW_MATRIX` → 世界坐标。
   （早期版本自己传 `inv_proj`/`inv_view`：只要取相机矩阵那一步失败，整套 uniform 写不进去，
   全屏面**一次都不出图**——排查了很久。）
2. **高度下限锚点必须是"地面"，不能是圆心**：
   `above = smoothstep(ground_y - margin_down, ground_y - margin_down + 1.0, wp.y)`；
   选点器传 `ground_y = min(角色脚下 y, 圆心 y)`。
   早期把它锚在**圆心**：鼠标指到围栏上时圆心被抬到 3.02m，允许范围整体上移 →
   **整片地面掉出范围**，只剩高物体被刷白（用户截图实测）。
3. `edge`（两条边线）与 `rim`（外弧）**都必须乘 `outer_ok`**，否则画在大面积物体/大网格上时
   边线会沿射线延伸到"天边"（实测白色光带）。

### 3.2 选点器 `spell_targeting.gd` 的屏幕空间部分

| 函数 | 职责 |
|---|---|
| `_ensure_screen_pass()` | 创建材质 + 把 4×4 的 QuadMesh 挂到**当前相机**下（z=-1，`extra_cull_margin=16384`，`render_priority=127` 保证排在透明队列最后，不再被草/粒子盖住） |
| `_update_screen_pass()` | 每帧写 `shape_mode`/`sector_center`/`axis`/`half_angle`/`radius`/`inner_m`/`ground_y`/`fill_strength`/`edge_strength`，并 `visible = true` |
| `_hide_screen_pass()` | 隐藏（`end()` / 切回圆盘 / `_exit_tree()` 都必须调） |
| `_exit_tree()` | 额外 `queue_free()` 全屏面（它挂在相机下，不是本节点的子节点） |

### 3.3 圆心判定（disc 模式）

```
相机→鼠标 射线：mask = (0xFFFFFFFF & ~ray_ignore_layer_mask) | prop_visual_layer_mask
     ↓
命中体分类（**层 / 组 语义判定，不比高度、不做逐面脚本**）：
   · 含地形层（运行时识别，本工程 = 2）        → 地面 → 指哪画哪
   · 在组 "ground" 或名字含 ground/floor/road/path/路面/石板/道路/台阶/地板（向上查 4 层）
                                              → 地面 → 指哪画哪
   · 其它（真实障碍 / Layer 16 精修几何）      → 物体 → 只对**地形层**打一条垂直射线，落到其下方地面
```

## 4. Layer 约定（**本项目最重要的一张约定表**）

| 层 | 值 | 谁在用 | 选点判定 |
|---|---|---|---|
| Layer 2 | `2` | 地形（Terrain3D 碰撞） | **地面** ✓ |
| **Layer 3** | **`4`** | **导入模型的"假碰撞盒"**（比可见网格大一圈）、道具/建筑 | **射线忽略**（`ray_ignore_layer_mask = 1<<2`）✗ |
| Layer 4 | `8` | 角色 mask 里的第三层 | 正常参与 |
| **Layer 16** | **`32768`** | **精修三角网格**（编辑器/插件烘焙，`mask = 0`）——**只给选点探测用** | 命中即"物体"，几何精确、能穿栅栏缝 ✓ |
| 玩家移动 | mask `2\|4\|8 = 14` | 完全**看不到** Layer 16 → 不会卡进凹面 ✓ |

> ⚠️ 曾经的严重错误：把 Layer 3 的**值 4** 当成"Layer 4"，于是排除掩码写成 `1<<3`（值 8），
> 结果是**等于没排除**，判定继续被假碰撞盒污染。凡涉及层的判断，**先打印 `collision_layer` 的实际值**。

### 4.1 精修几何（Layer 16）怎么来

* 编辑器：选中 `MeshInstance3D` → 创建碰撞形状（**同级节点 + 三角网格**）→ 把生成的
  `StaticBody3D` 的 `collision_layer` 设为 `32768`、`mask = 0`；
* 先**减面**再做（导入高模动辄几十万面）；
* **禁止运行时批量生成**（见 §7.4）。

### 4.2 代价

| 项 | 量级 |
|---|---|
| 内存（物理侧） | ≈ 网格顶点同量级（3 万面 ≈ 1~2MB/件） |
| 加载时构建 BVH | 一次；几件 ≈ 几十 ms |
| **每帧** | **≈ 0**（静态 body 不 tick、不变换；只有"瞄准时 1~2 根射线"） |
| 其它物理 | `mask = 0`，玩家 mask=14 → 不参与任何碰撞 ✓ |

### 4.3 审计结论（谁会命中 Layer 16）

全工程只有 `spell_targeting.gd`（挖空的 mask）与 `flame_scorch.gd`（贴地探测）会主动命中；
`player.gd`(14)、`camera_rig.gd`(4 / 2)、`main.gd`(4) 都不会 ✓。
**约定**：以后写"全层查询"（`0xFFFFFFFF`）要么显式排除 Layer 3/16，要么只写需要的层。

### 4.4 火焰灼烧的贴地探测（两级）

```
第一级：mask = (全部 & ~Layer3) | Layer16   → 真实几何（能穿缝、不被假盒抬高）
第二级：mask = 全部                          → 仅当比第一级高出 > 0.35m 时采用
        （说明那一件只有假盒、没烘精修几何 → 用它的顶面，免得火焰掉到物件脚下）
```
成本：多一根射线（微秒级）。

## 5. 火焰推进（`flame_advance.gd`）要点

| 需求 | 实现 |
|---|---|
| 扇形两边/外弧的火焰**最大面朝扇形中轴线**、弧上的**朝角色** | `fire_burst.face_cards_to(世界方向)` 对**每一张焰卡**单独施加 yaw（`random_yaw` 会把集群旋转冲掉） |
| 角色脚底不生成火焰 | `place_inner_gap_m`（默认 0.5m）+ **两遍布点**：① 按名义半径摆一遍 → ② 量每簇**实际水平伸距**（`_patch_reach()`，AABB 角点法），取最大值 + 留白作为最内侧半径，用 `_remap_inner()` 整体重映射再摆一遍（避免簇挤在一圈） |
| 火焰不要太远 | 早期用"保守上界"（逐级位移相加 + 最坏横向倍率）会比真实伸距大 0.8~1.0m，把整圈火推远 ✗ → 改成上面的**实测两遍** ✓ |
| 贴地光斑必须跟随移动 | 早期 `_glows` 材质共享、位置未复原 → 15 个光斑全部停在 `Main` 原点、8.98m 外"远处有火" ✗ → 现在在 `_place_one()` 里显式设置位置/朝向/缩放 |

调参：`place_inner_gap_m`（脚底留白）、`place_inner_m`（最小内圈）、`fire_scale` / `place_scale`。

## 6. 公共模块 `surface_overlay.gd`（与【物体探测】共用）

| API | 说明 |
|---|---|
| `attach(mi, mat, ghost)` / `detach(id)` | 挂/摘 `material_overlay`，并记录与还原 `prev_overlay / prev_transparency / prev_layers` |
| `sync(want)` | 同步"当前该挂的集合"，不在集合内的自动还原 |
| `clear()` | 全部还原（法术结束/节点退出必须调） |
| `mark_layers(mi, mask)` | 屏幕空间描边那种"只丢进遮罩层"的用法 |
| `visible_meshes / resolve_visual / visual_aabb` | 静态工具；`resolve_visual` **向上找 3 层**（本工程碰撞体与网格常是**兄弟**） |
| `collect_meshes(...)` | 球查询 + 解析可视节点 + 包围盒，`filter` 由调用方给 |

【物体探测】用它挂"描边 + `next_pass` 扫描带"；选点器曾用它挂"物体表面扇面"（现在被屏幕空间覆盖取代，
保留开关备用）。

## 7. 踩坑与结论（**最有价值的一节**）

| # | 坑 | 结论 |
|---|---|---|
| 7.1 | **射线贴合网格**（CPU 采样建高度场 Mesh） | 弦切割（凸地形的弧形暗带）、台阶/竖面无解、边缘拉裙边、与视觉地形穿模、"中间一块白一块不白" —— 用几何逼近曲面的所有失败模式都出现过 ✗ |
| 7.2 | **投影贴花 Decal** | 盒体 + 贴图：分辨率决定边界清晰度；盒高则把草刷白、盒矮则盖不到高物体（两难）✗。另：`Image.create()` 在 Godot 4.4+ 已废弃，失败会让 `texture_albedo` 为空 → Decal 退化成"用 modulate 铺满整个盒体" = 一整块方块白 ✗ |
| 7.3 | **逐物体挂 `material_overlay`** | 天然是 opt-in："发现不了就不涂" → 巨组包围盒/过滤条件一改就"整片不涂" ✗；且包围盒（AABB）分不出"镂空/内凹"与"实体" ✗ |
| 7.4 | **运行时批量 `create_trimesh_shape()`** | 几十件高模一起建 BVH + 内存暴涨 → **加载与运行直接卡爆** ✗。碰撞数据必须**离线/编辑器烘焙** |
| 7.5 | **GDScript 逐三角面求交** | 又慢又脆：大网格每次遍历上万面（实测"格内三角面 25830 个"）；按顶点格登记时大三角面会被漏掉（指着石头却判"空气"）；上限截断会把要用的面切掉 ✗ → 正解是让**物理引擎**做（Layer 16）|
| 7.6 | **用"高度"区分地面/物体** | 基准取错（圆心被鼠标抬到围栏顶 3.02m）时，整片地面被过滤 ✗；"比地面高多少"本质上分不清"障碍"与"透过缝隙看到的另一物体" ✗ → 改用**层/组语义** ✓ |
| 7.7 | **全屏面挂在相机下** | `visible = false` 关的是选点器自己，关不掉全屏面 → 技能放出后白色扇形残留 ✗；且 `_process` 里"先打开又立刻隐藏"的顺序错误会让圆环永不显示 ✗ |
| 7.8 | **headless 下 `RenderingServer.frame_post_draw` 不触发** | 出图脚本必须先判断 `DisplayServer.get_name() != "headless"`，否则永久等待 ✗ |
| 7.9 | **Godot 4 API 细节** | `MeshInstance3D.get_surface_count()` **不存在**（在 `Mesh` 上）；`create_trimesh_shape()` 返回值需显式标注类型才能通过本工程的"警告即错误"；`PhysicsShapeQueryParameters3D` 没有 `max_results` 属性（它是 `intersect_shape` 的第二个实参）|
| 7.10 | **自检要抗内部结构变化** | 自检读内部字典（如 `entry["meshes"][i]["mi"]`）会在重构后集体误报 ✗ → 提供兼容读取（`_mesh_of()`）|

## 8. 开关与调参表

| 开关（`spell_targeting.gd`） | 默认 | 作用 |
|---|---|---|
| `use_screen_pass` | **true** | 屏幕空间覆盖（定稿方案） |
| `use_decal` | false | 备用路径②：投影贴花 Decal |
| （两者皆 false） | — | 备用路径③：射线贴合网格（不依赖深度纹理，Compatibility 可跑） |
| `ray_ignore_layer_mask` | `1<<2` (Layer 3) | 选点射线忽略的层（假碰撞盒） |
| `prop_visual_layer_mask` | `1<<15` (Layer 16) | 精修三角网格层 |
| `screen_fill_strength` | 0.55 | 扇形填充 |
| `screen_fill_strength_circle` | **0.0** | 圆环填充（0 = 只有外弧亮带） |
| `screen_edge_strength` | 2.2 | 边线/外弧强度 |
| `screen_floor_margin` | 1000（已废弃） | 见 §3.1：高度下限锚点改为 `ground_y = min(脚下, 圆心)` |
| `DEBUG_LOG_PREVIEW` | true | **施放/结束**时打一次快照（鼠标/命中体/层/判定/圆心/半径），不是每帧 |
| `place_inner_gap_m`（flame_advance） | 0.5 | 火焰外缘离角色的留白 |
| `fallback_drop_m`（flame_scorch，函数内） | 0.35 | 贴地探测两级回退的落差阈值 |

### 8.1 日志快照字段（排查用）

```
[选点·施放/结束] 圆盘 鼠标=(751,214)px 地形层=2 判定=物体 -> 垂直落地
        命中=StaticBody3D 「StaticBody3D」layer=32768 组=- ｜ /root/Main/.../StaticBody3D2 @(x,y,z)
        圆心=(x,y,z) 半径=2.50 角色=(x,y,z) 圆心高于角色=0.04m 张角=45°
```
* `判定` 说明走了哪条分支；`命中=… layer=…` 直接暴露"打到的到底是什么层"（排查层错的关键）；
* `圆心高于角色` 若很大（>1m）通常意味着"圆心被鼠标抬到物体上了" ✗。
