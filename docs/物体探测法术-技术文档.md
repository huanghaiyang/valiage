# 物体探测法术 —— 技术文档

> 法术：**物体探测**（`detect_pulse`）—— 从角色脚下荡开一圈圈探测波；被扫到的物体会浮现
> 动漫风格描边，同时有亮带贴着物体表面游走过去；只探测地形之上、屏幕 1.2 倍区域内的可碰撞物体。
>
> 本文记录**实现原理、参数含义、验证方法，以及开发过程中踩过的坑**（第 12 节）。
> 坑那部分是刻意保留的：里面每个现象都真实发生过，且大多不是"手滑"而是引擎行为，
> 不记下来下次一定再踩。

## 2. 每帧数据流

```
_clock += delta
_boxes.clear()                      # 本帧被探测物体的世界包围盒（屏幕空间描边用）
_tick_pulses(delta)
    ├─ 每个脉冲: r += wave_speed * delta
    ├─ follow_caster ? 圆心 = 角色当前位置
    ├─ _apply_ripple(...)           # 只给着色器一个标量 progress = r / max_r
    └─ _detect(r, center, ...)      # 半径 r 的球形查询 -> 过滤 -> _outline()
_update_reveal()                    # 把波面半径写进描边/扫描材质
_update_screen_outline()            # 屏幕空间路线专用（当前 return）
_expire_outlines()                  # 到期撤销 material_overlay
```

**关键点**：`_detect` 每帧对**每个脉冲**跑一次。视觉上只有一圈，但那一圈背后是一次真实查询。

## 3. 波纹模型：真·多圈

### 3.1 一圈 = 一个脉冲

早期实现是"1 个脉冲 + 着色器自己拖一串视觉余波"，也就是说**只有最外圈是真的，内圈纯装饰**。
现在改成：**每个脉冲只画一圈**，`repeat_interval` 决定多久发一个新脉冲。

```glsl
// detect_ripple.gdshader
float s = cos((r - front) * TAU / wavelength);              // cos：峰值正好在波前
float rings = pow(max(s, 0.0), sharpness)
            * exp(-pow((front - r) / ring_window, 2.0));    // 高斯窗口截断 -> 只剩一圈
```

`ring_window = 1.5` 米，所以哪怕 `wavelength = 9` 米也只保留波前附近那一圈。

### 3.2 两条必须记住的关系

```
圈间距   = wave_speed × repeat_interval      （默认 26 × 0.28 ≈ 7.4 米）
同时圈数 = max_radius ÷ 圈间距               （上限 8，由 SCAN_MAX_WAVES / vec4[8] 决定）
```

实测：6 个脉冲并存，半径 `[34.7, 34.2, 26.9, 19.5, 12.1, 4.8]`，间隔 7.4 米 ✓

超过 8 圈的会**不被扫描带着色器处理**（波纹仍画得出来）——这是刻意的上限，防止着色器循环爆炸。

### 3.3 多脉冲下的一个隐蔽 bug（已修）

同一个物体每帧会被**多个**脉冲命中（球查询覆盖整个圆盘）。原来写的是

```gdscript
entry["pulse"] = pulse     # ← 会被"最后命中的最小圈"覆盖
```

于是揭示半径跟着内圈走，**已经扫过的轮廓会往回缩**。正确做法是只保留半径最大的那个：

```gdscript
var cur = entry.get("pulse")
if cur == null or float((cur as Dictionary)["r"]) < float(pulse["r"]):
    entry["pulse"] = pulse
```

## 4. 探测：查询与过滤链

### 4.1 球形查询，不是薄环

```gdscript
var hits := space.intersect_shape(params, max_results)   # 半径 r 的球，位于 center + UP*0.5
```

**为什么不用薄环**：26 m/s 下每帧推进 0.43 米；薄环在高帧间隔（掉帧）时会**穿透**小物体而漏检。
球的代价是"波前以内的整个圆盘每帧重复查询"，换来的是不掉检。

### 4.2 过滤链（按顺序）

| 步骤 | 函数 | 说明 |
|---|---|---|
| 1 | 排除 RID == 玩家 | 不描自己 |
| 2 | `_resolve_visual(climbs ≤ 3)` | 碰撞体**没有网格子节点**，网格是**兄弟节点** —— 必须向上找到真正的可视节点 |
| 3 | `_is_detectable` | 玩家祖先排除；类名含 `terrain` 排除；`exclude_name_hints` 命中的祖先名排除 |
| 4 | `_above_terrain` | 从物体上方朝下打射线，**必须打到地形** —— 保证"只探测地形之上" |
| 5 | `_in_screen_margin` | 8 个 AABB 角投影后做矩形相交（不是判中心点！） |
| 6 | `_outline` | 记录并挂材质 |

**关于第 5 步**：最初用"AABB 中心是否在屏内"，结果 17 米宽的大件被判出界、整个不描。
改成"8 角投影 + 矩形重叠"才对。**取不到可用相机时返回 true**（fail-safe，宁可多描不误杀）。

### 4.3 `exclude_name_hints` 的定位

它是**廉价的兜底**，不是主机制。当前值：

```
terrain,ground,grass,bush,flower,plant,leaf,foliage,weed,shrub,fern,clover,草,花,灌木,植物
```

匹配方式是**沿可视节点向上逐级匹配祖先名字**，所以 `WorldBrushInstances/grass_bermuda_01_xx/...`
只要祖先里有 `grass` 就整体排除。

> ⚠️ 靠名字判断本身是脆弱的（用户当时也质疑过）。真正"结构性"的排除来自第 6 节的
> **材质只加在被探测物体上** —— 草压根不在探测集合里。名字只是额外保险。

## 5. 描边：反壳（inverted hull）—— 当前生效方案

### 5.1 三步原理

```glsl
// 1) 顶点沿"远离视线轴"外扩（视图空间）—— 屏幕上剪影整体胀一圈
vec4 view = MODELVIEW_MATRIX * vec4(VERTEX, 1.0);
view.xy += normalize(view.xy) * (line_px * screen_k * max(-view.z, 0.01));
POSITION = PROJECTION_MATRIX * view;
```

```glsl
render_mode blend_mix, unshaded, cull_front,   // 2) 只画背面
             depth_draw_never, ...              // 3) 内部交给**普通深度测试**挡掉
```

- **内部**：壳的背面在物体自己**后面** → 深度测试失败 → 不画
- **外缘**：轮廓之外没有遮挡 → 背面画得出来 → 一圈线

### 5.2 像素恒定线宽

```
grow = line_px × (2·tan(fov/2) / 屏幕高) × 视深度
```

`screen_k = 2·tan(fov/2) / 屏幕高` 由脚本写入，所以**远近一样粗**（单位是像素，不是米）。
这是比"世界单位外扩"更好的做法：世界单位外扩时远处的线会细到看不见。

### 5.3 为什么这条对"草"是结构性免疫

材质是**逐个物体**叠加的（`material_overlay`），只加在被探测到的物体上。
草不在探测集合里 → 永远不会被描。**不靠名字、不靠遮罩、不靠过滤。**

### 5.4 逐步揭示

```glsl
float dist = distance(wp.xz, wave_center.xz);              // 片元的世界 XZ 位置
float reveal = 1.0 - smoothstep(wave_radius - reveal_soft,
                                wave_radius + reveal_soft, dist);
if (reveal <= 0.002) discard;
```

`wave_radius = 该物体的脉冲半径 + reveal_ahead(1.2)`。`reveal_ahead` 是为了消掉
"轮廓等波面扫到才画"造成的**半拍延迟感**。

## 6. 表面扫描带：亮带在物体表面游走

挂在描边材质的 **`next_pass`** 上（同一次绘制的后续 pass），所以一个 `material_overlay`
槽位就能同时有描边 + 扫描带。

### 6.1 单圈相位

```glsl
d      = 到该圈圆心的水平距离
r_here = 该圈半径 - 高度 × climb        // 越高处到达半径越小
x      = r_here - d
  x ≈ 0  正在被扫过 → 前沿亮带（高斯）
  x > 0  已扫过     → 身后余辉 exp(-x / trail_len)
  x < 0  还没扫到   → 不画
```

**`climb` 是手感的关键**：纯水平环只是"把地面波纹投影到物体上"；加上高度项后波面会
**沿着表面往上爬**，才有"扫描仪扫过去"的感觉。

### 6.2 多圈叠加

```glsl
uniform vec4 scan_waves[8];   // (圆心.x, 圆心.z, 半径, 0)
uniform int wave_count;
```

片元里对每圈累加能量 → **每一圈都会依次扫过物体表面**，而不是只有最外圈在扫。
`_update_reveal()` 每帧把当前所有脉冲打包成定长 8 元素数组传进去。

> ⚠️ 因为是**叠加**，`trail_gain` 必须调低（0.35 → 0.10），否则 6 圈余辉加起来会把
> 石面糊成一片白（实测过）。

## 7. 地面波纹着色器细节

| 细节 | 做法 | 原因 |
|---|---|---|
| 形状 | 平面 + 按径向距离画 | 实体 torus 管太粗；贴地圆环在起伏地形上会被埋进土里；且一道环没有层叠感 |
| 抬升 | `wave_lift = 0.12` | 免得被地表吃掉 |
| 噪声扭曲 | **世界坐标** `vnoise(wp.xz * k)` | 用极坐标 `atan` 的角度做输入时，角度在 ±π 处**跳变** → 波面出现一条径向**接缝**（实测出现过）。世界坐标噪声处处连续，且频率以"米"为单位，起伏尺度不随半径变化 |
| 加色 | `blend_add` + `unshaded` | 纯发光，不参与光照 |

## 8. 屏幕空间描边（保留，默认关闭）

`screen_outline = false` 时下面的东西**全部不生效**（`_update_screen_outline()` 直接 return）。

它是 UE「Custom Depth / Stencil + 后处理描边」的 Godot 等价物：

| UE | Godot |
|---|---|
| `Render CustomDepth Pass` | `mesh.layers \|= MASK_LAYER` |
| Custom Depth 缓冲 | `SubViewport` + `Camera3D(cull_mask = MASK_LAYER)` |
| 共享场景 | `own_world_3d = true` **再**赋 `world_3d` |
| 后处理采样 `SceneTexture:CustomDepth` | 全屏四边形 + `hint_default_black` 的 mask 纹理 |
| 邻域边缘检测 | 八邻域取 max，`edge = 中心在内 && 邻居在外` |
| stencil 只选某类物体 | mask 图里天然只有被探测物体 |
| dilation 控制线厚 | `screen_sample_px` |

外加一层 **AABB 三维判定**：像素世界坐标必须落在某个被探测物体的包围盒内。

**为什么不用它做默认**：见 12.4/12.5，这条路有几个引擎层面的坑，验证成本高；
而第 5 节的反壳方案**同样能结构性排除草**，且简单得多。

## 9. 生命周期与时间基准

- 时间用**自己累加的 `_clock`**（`_now()`），不是 `Time.get_ticks_msec()` —— 后者在
  暂停/单步时会造成轮廓提前或延后消失。
- `entry["until"] = _now() + outline_life`，**每帧刷新**（只要还在被探测）。
  因此实际语义是"**波还在覆盖它期间一直显示，最后一次命中后 1 秒消失**"，
  而不是"被某圈碰到后精确 1 秒"。
- 到期：`_expire_outlines()` → `_clear_entry()` → 还原 `material_overlay` / `transparency`。
- `_exit_tree()`：清所有轮廓、释放波纹节点、释放挂在**相机**下的全屏面与遮罩子视口。
  （✓ 全屏面挂在相机下，不显式回收就会永久留在相机上。）

## 12. 事故档案（每个坑都是实测过的）

### 12.1 碰撞体没有网格子节点

**现象**：探测到物体但 `outlined = 0`。
**根因**：导入的 Tripo 模型里，`StaticBody3D` 与 `MeshInstance3D` 是**兄弟**关系，
不在碰撞体下面。
**修**：`_resolve_visual()` 从碰撞体沿父链向上最多 3 层找真正的可视节点，并按**可视节点**
（不是按碰撞体）去重 —— 否则同一批网格会被两组抢 `material_overlay`，还原顺序一乱就留下永久描边。

### 12.2 屏幕裁剪用 AABB 中心 → 误杀大件

**现象**：17 米宽的大件全都不描。
**修**：改成 8 个 AABB 角投影 + 矩形重叠；取不到相机时返回 true（fail-safe）。

### 12.3 反壳 + "手工查深度 discard" → 只在背向镜头一侧有线

**现象**：轮廓只出现在物体背向角色的一侧。
**根因**：在反壳基础上**额外**加了一段"查深度纹理后 discard"去内部。那一步把靠镜头这侧的
壳层（被地面/物体本身压在后面）一起丢掉了。
**修**：**删掉那段手工 discard**，内部交给**普通深度测试** —— 深度测试本来就够用。
> 这一条是整份文档里最值得记的：我加了一段"看起来更严谨"的逻辑，反而破坏了标准做法。

### 12.4 CPU 回读遮罩图 → 误判"遮罩没渲染"，把好方案关掉

**现象**：`SubViewport` 遮罩测出来"最大亮度 0.0 / 全黑"，据此判定遮罩通道失效并关闭方案。
**根因**：Godot 未修复的 issue
[#91828 `Viewport.get_texture()` not correct when alpha != 1.0](https://github.com/godotengine/godot/issues/91828)
—— `transparent_bg` 打开时 **CPU 回读数据不可信（返回全 0），而 GPU 端采样同一张纹理是正常的**。
配套的 [#94332](https://github.com/godotengine/godot/issues/94332)：`transparent_bg` 下
`has_alpha()` 返回 false（对应实测"alpha 全 0"，因为不透明几何体不写 alpha）。
**教训**：**用不可信的量当判据，会连改三轮渲染配置**。观感类改动只认截图。

### 12.5 遮罩子视口的渲染前置条件

实测结论（每条都用读数确认过）：

| 配置 | 结果 |
|---|---|
| `own_world_3d = false`，只赋 `world_3d` | `world_3d` 读出来是 **null** → 什么都渲染不出来 |
| `own_world_3d = true` **再**赋 `world_3d` | `world_3d` 非空 ✓（**必须按这个顺序**） |
| 给遮罩相机设自定义 `Environment` | 整张遮罩全黑 |
| `transparent_bg = false` | 只剩清屏色，仍无物体 |

位匹配本身**是正确的**（实测 `mesh.layers = 129`、`cam.cull_mask = 128`、AND 非零）。

### 12.6 阈值 0.5 判"是否在遮罩内" → 一条线都没有

遮罩图里是物体**受光后的颜色**（可能很暗），`step(0.5, ...)` 恒为假。阈值必须取极小值
（0.005）。同理，屏幕空间路线的深度梯度阈值取 0.6 会把草一起描，2.2 才只剩大物体。

### 12.7 把 AABB 过滤挂在一个关掉的开关上 → 过滤完全失效

**现象**：`box_count = 0`，草（含 `simplegrasstextured` 的 MultiMesh 草）全被描，比之前更差。
**根因**：收集条件是 `if screen_outline and mask_by_objects:` —— 遮罩关着就永远不收集。
**修**：解耦成 `if screen_outline:`。
**教训**：**每改一个开关，立刻量它自己那个计数器**（`box_count` 这种），别只看画面。

### 12.8 让线宽严格 1px → 线断成一个个点

把深度梯度的过渡带收到 `0.92→1.0`，结果轮廓**断成虚线**：轮廓上的梯度并非处处都那么陡。
**修**：过渡带回落到 0.55。**纯深度梯度法做不到"严格 1px 且连续"**，这两个目标在该方法里互斥。
（反壳方案天生没有这个问题。）

### 12.9 `INV_PROJECTION_MATRIX` 不能放进用户函数

**现象**：`SHADER ERROR: Unknown identifier in expression: 'INV_PROJECTION_MATRIX'`。
**原因**：Godot 的着色器内置量只在**阶段入口函数**（`fragment()`）作用域里可见。
**修**：把采样内联进 `fragment()`。
**同类**：`fragment()` 里**不能写 `return`**（只能 if/else）、`INSTANCE_CUSTOM` 只在 `vertex()` 可读、
`shader_type` 只能出现一次。

### 12.10 `PhysicsShapeQueryParameters3D.max_results` 不存在

它只是 `intersect_shape(params, max_results)` 的第二个参数。误写成属性会把游戏**卡进调试器断点**。

## 13. 已知限制

1. **同时最多 8 圈**参与表面扫描带计算（`SCAN_MAX_WAVES`，与 `vec4[8]` 对应）。
   波纹仍然画得出来，只是第 9 圈起不再影响物体表面。
2. **轮廓寿命语义**：是"波覆盖期间持续显示 + 最后命中后 `outline_life` 消失"，
   不是"被某一圈碰到后精确 N 秒"（见第 9 节）。
3. `follow_caster = true` 时圆心与半径同时移动，**已扫区域会被重复扫**；
   若想要"定死在施放点扩散"的语义，把它设为 false。
4. `ghost`（物体半透明）**加了但未实测**。
5. `screen_outline = true` 那条路**未完成验证**，默认关闭；其遮罩通道的具体渲染问题见 12.4/12.5。
6. `exclude_name_hints` 依赖节点命名，属于脆弱兜底（真正机制见 5.3）。

## 14. 接入方式（新增法术时参考）

法术统一接口（`spell_caster.gd` 约定）：

```gdscript
func setup(player: Node3D, staff: Node3D) -> void
func start_cast() -> void
func stop_cast() -> void
func is_casting() -> bool
func aim_dir() -> Vector3
func origin_global() -> Vector3
func ran_out_of_mana() -> void
```

注册三步：

```gdscript
# 1) spell_caster.gd
SPELLS["detect_pulse"] = preload("res://scripts/spells/detect_pulse.gd")

# 2) spell_wheel.gd
SPELL_NAMES["detect_pulse"] = "物体探测"
ASSIGNED[3] = "detect_pulse"       # 第 3 槽位

# 3) 法术脚本里用 Mana autoload 扣蓝
if not Mana.try_spend(mana_per_cast): return
```

操作：**Q** 唤出/收起法术轮盘（`spell_wheel`），**E** 是场景交互（`main.gd` 的 `_try_interact`，
法术不占用 E）。
