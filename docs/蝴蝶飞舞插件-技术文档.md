# 蝴蝶飞舞插件 — 技术文档

> 代码：`addons/butterfly_swarm/` ｜ 着色器：`assets/shaders/butterfly_wings.gdshader`
> 使用说明：`addons/butterfly_swarm/README.md` ｜ 接口契约与实测清单：`addons/butterfly_swarm/CONTRACT.md`
> 测试：`tests/test_butterfly_swarm.gd`（无头自跑：`tools/verify_butterfly.gd`）
> 素材：`assets/textures/活体/蝴蝶/`（20 张真透明底 PNG）

---

## 1. 目标与拆解

用户要求：**多选蝴蝶 PNG** → **在指定 3D 区域内随机飞舞** → **有 AI 行为** → **图片居中折成蝴蝶形状** → **接入天气（尤其风）**。

拆成 5 个可独立验证的部件：

| 部件 | 文件 | 关键技术点 |
| --- | --- | --- |
| 素材 IO | `butterfly_io.gd` | 逐像素量**不透明包围盒**（自动裁剪 / 定折轴 / 定宽高比） |
| 单只蝴蝶 | `butterfly.gd` | 单位方块网格、逐帧扑翼、状态机 + Boids、能量 |
| 群组 | `butterfly_swarm.gd` | 多选素材、区域、逐帧驱动、风/天气接入、`@tool` 即时预览 |
| 外观 | `butterfly_wings.gdshader` | 绕体轴折叠成 V、双面、UV 裁剪、受光 + 虹彩 |
| 编辑器集成 | `plugin.gd` + `inspector_batch.gd` + `tools/` | 菜单/工具栏、**检查器批量面板**、多选对话框、素材扫描、预览场景生成 |

**为什么做成 `@tool` 节点 + 薄插件**：节点本身 `@tool`，检查器里改参数**不运行就能看到蝴蝶**；
插件只提供快捷键入口（添加/注入/选素材/重扫/开预览）。这样即使用户停用插件，场景里的蝴蝶照样飞。

## 2. 「居中折叠」的完整推导

### 2.1 先量再贴：为什么要自动裁剪

素材的不透明区域占比实测差异很大：**宽 0.7407~0.9046、高 0.7439~0.9539**（20 张）。
直接贴整图 → 每只蝴蝶实际大小差 **22%**、上下留白还各不相同。所以先量包围盒，只贴那一块。

**折轴取"包围盒的水平中心"而不是全图中心**：实测全图中心与真实蝶身最多差 4% 全宽
（蝶身横轴 0.4621，见 蝴蝶-15），用全图中心那张图的蝶身会明显偏离折缝。
（逐行包络中点的加权平均 `body_x` 会被"单侧翅占满整行"带偏，所以只留作诊断值，不当折轴。）

### 2.2 坐标系：体轴是 Y，飞行方向是 -Z

```
        +Y（尾）
         ^
  -X <---+---> +X      +X = 纹理 +u（翅尖）
         |             -Y = 头
        +Z = 额面法线
```

* **折轴 = 体轴 = 局部 +Y**（头尾方向）→ 绕它转，翅面才**离开原平面**、获得真实前后厚度。
* **飞行方向 = 局部 -Z**：为了与 Godot `look_at()` 的约定一致（它把 **-Z** 对准目标）。
  `_sync_transform()` 的"树内 / 树外"两条分支必须同向（见 §5 的踩坑记录）。

### 2.3 折叠数学（着色器顶点阶段）

```glsl
float th = radians(dihedral);
float sx = (VERTEX.x < 0.0) ? -1.0 : 1.0;   // -1 = 左翅
float a  = -th * sx;                        // 右翅 -th，左翅 +th
float c = cos(a), s = sin(a);
VERTEX = vec3(VERTEX.x * c, VERTEX.y, -VERTEX.x * s);   // 绕 +Y
VERTEX.z += fold_dz * VERTEX.x * (sx < 0.0 ? 1.0 : -1.0);
VERTEX.z += bend_y * VERTEX.y * VERTEX.y;
vec3 nr = vec3(sin(a), 0.0, cos(a));        // 与旋转同源的解析法线
```

`dihedral=45°` 时翅尖（`x=±0.5`）离面 `0.5·sin45° = 0.3536`，左右翅尖同侧同量 →
**真的折出一个三维 V**（书脊朝下、双翅上举）。这一条被测试 `test_fold_axis_geometry_verdict`
当成数学事实钉住（还额外断言 shader 源码里确实含 `-VERTEX.x * s`）。

### 2.4 一次被推翻的改动（必须留痕）

中途曾以"侧视会变成竖条"为由把折轴改成 **+Z**。**那是错的**：

* 绕 **+Z** 是**平面内自转**（`z` 分量原样保留）⇒ 网格永远**共面于 z=0** ⇒
  **从任何视角都不可能出现 V 形折缝**，两片翅还会在身体附近共面交叉；
* 法线 `(sin a, −cos a, 0)` 的 z 恒为 0 ⇒ 法线**切于自身表面** ⇒ 方向光一片平光。

真机实拍复核：折缝拍不到、翅面呈交叉刀片。回退到 +Y 后同一机位**能看到折缝**，且：

| 指标 | 6° | 45° | 结论 |
| --- | --- | --- | --- |
| 翼展（局部 X）投影 | 264 px | 206 px（**0.78×**） | 变窄发生在翼展方向 = 绕 +Y 的签名 |
| 头尾（局部 Y）投影 | 180 px | 198 px（1.10×） | 头尾几乎不变 |
| 左右半亮度比 L/R | 1.024（±2.4%） | **1.144（±14.4%）** | 两翅法线真的不同 → 真 3D |
| 斜视角最大列落差 | 0.171 | **0.216** | `fold_front.png` 里折缝可见 |

> 教训：**"做了一次旋转"是防不住这种错的**。判断折叠对不对，要看"有没有离开原平面"
> （`z` 分量是否依赖 `x`），而不是看有没有调用三角函数。

### 2.5 ★★ 体积感：为什么"蝴蝶像纸片"，以及怎么解决 ★★

**根因**：素材是**一张零厚度的平面**，无论怎么折都只是一张纸 ——
正视一片均匀色（没有明暗渐变）、侧视一条线（没有边）、掠射没有高光（没有体积）。

解决不是单点技巧，而是**三条独立手段**（每条都能单独关闭，便于 A/B 对比）：

| # | 手段 | 位置 | 做什么 | 关掉它的参数 | 为什么有效 |
| --- | --- | --- | --- | --- | --- |
| ① | **弧度 camber** | 着色器 | 二面角随翼展位置**线性增长**（根部平、翅尖翘） | `wing_camber = 0` | 翅面成为**曲面** → 方向光产生连续明暗渐变（平板永远只有"整片亮/整片暗"） |
| ② | **厚度外壳** | `butterfly.gd` 生成几何 | 前层 + 后层 + 四条**侧壁** = 闭合薄壳 | `wing_thickness = 0` | 侧视是"有宽度的边"而不是一条线；边缘能吃到高光 |
| ③ | **实体身体** | `butterfly.gd` 生成几何 | 沿头尾的 8 边形**纺锤实体**（颜色从素材中轴采样） | `body_scale = 0` | 从**任何**角度看都有质量，是"蝴蝶不是贴纸"的决定性因素 |

再加两项廉价强化：**边缘环压暗**（`rim_dark`，代替没有 AO 的立体感）与
**一点镜面高光**（`SPECULAR = 0.45`，配合曲面法线会出现随姿态移动的高光条）。

**三条硬约束（全是实测踩出来的）**：

1. **厚度不能在顶点着色器里做**：Godot 顶点阶段**没有 `FRONT_FACING`**，
   写它会 `Unknown identifier in expression: 'FRONT_FACING'` 并让**整份着色器编译失败**。
   所以厚度只能用几何做（②）。
2. **`camber` 的基准角必须是 `max(th, 30°)`**：直接用 `th` 会让"张翼角 = 0（完全平飞）"时
   曲率一起归零、翅面退回平板（这条是被测试 `test_fold_axis_geometry_verdict` 抓出来的）。
3. **给 `surface_override_material(1, …)` 前必须确认 surface 1 存在**：
   `body_scale = 0` 时不建身体面，此时设 index 1 会报
   `Index p_surface = 1 is out of bounds`。

**网格结构**（`GRID_X = GRID_Y = 8`）：

| surface | 内容 | 顶点数 |
| --- | --- | --- |
| 0 | 翅面闭合外壳（前层 81 + 后层 81 + 侧壁 768） | 930 |
| 1 | 身体（8 边形 × 6 环 + 两端封口） | ~112 |

> 20 只 ≈ 2 万顶点，现代 GPU 可忽略；但**别把 GRID 调到 32 以上**（按平方涨）。

**数值验证**（不靠像素统计，因为素材本身左右不对称会假报警）：
左翅 `(-x, y)` 与右翅 `(+x, y)` 折叠后应满足 `x_l = −x_r`、`y_l = y_r`、**`z_l = z_r`**，
实测在 `camber ∈ {0, 0.3, 0.8}` × 25 个采样点上**最大镜像误差 = 0.0**（机器精度），
且两翅 z 都 > 0（V 的开口朝向额面法线一侧）。

> ⚠ 这里踩过一个坑：判据一开始把 z 写成"相反数"（`z_l = −z_r`），报出 **0.829 的假失败**。
> 实际几何是**两翅同向抬起**，z 必须**相等**。教训：符号类判据要用数值验、别靠脑内推。

## 3. AI 行为设计

### 3.1 状态机（能量 / 威胁 / 天气共同驱动）

优先级：`FLEE`（受惊）> `SHELTER`（恶劣天气）> `BASK`（回能）> `SEEK`/`COURT` > `CRUISE`。

* **CRUISE**：漫游方向被**低频噪声**缓慢推着转（不是每帧随机），再叠高频小噪声让轨迹"一顿一顿"。
* **SEEK**：查 `butterfly_target` / `flower` 分组，朝最近的目标飞（距离越近推力越小 → 盘旋而非撞上去）。
* **COURT**：与随机同伴绕飞。
* **BASK**：能量 ≤ `rest_energy` 时落地停歇回能，翅膀合拢到 ~92% 上限。
* **SHELTER**：`Weather.wind ≥ shelter_wind` 或 `rain ≥ shelter_rain` 时下沉到区域低处避风。
* **FLEE**：威胁 4 m 内触发，朝反方向冲刺并拔高。

### 3.2 转向力（每帧合成后限幅积分）

```
主动力（按状态） + 同群分离 + 风的拖曳 + 边界软回弹 + 避地
```

* **分离力**：`1/r` 权重，垂直方向权重减半（允许上下错开而不用绕开）。
  **不做 cohesion/alignment** —— 蝴蝶不是鸟群，靠拢反而假。
* **风的拖曳**（接入天气的核心）：直接把 `velocity` 朝风向插值，
  再叠一个与风向垂直的抖动力（吹得歪歪扭扭），最后按顺/逆风补一点推力（免得整群被吹出区域后回不来）。
* **边界**：力**随超出量线性增长**。第一版用固定力，实测阵风下会外溢 **0.392 m**；
  改成"带宽内 3 m/s²、带宽外按超出比例放大到 30 倍"后，实测越界 **0.000 m**。
* **积分**：`force.limit_length(accel*3)` → `velocity += force*dt` → 限速 → `position += velocity*dt`。
  速度几乎为零时给一个随机方向兜底，避免"悬停死"。

### 3.3 为什么 AI 必须是纯数学

无头 CI 没有渲染，但**要验证 AI 能跑、不越界、不钻地、可复现**。所以：

* `advance()` 里只有向量运算；节点变换更新放在末尾，并带**树外回退**（见 §5）。
* 随机全部走**注入的 RNG**（种子 = `seed_value*1000003 + i*7919`）→ 同种子完全可复现
  （实测 seed=999 两次跑出的终点坐标逐位相等）。
* 坐标系：AI 全在**群组本地空间**算（区域是节点上的常量盒子），需要世界坐标的地方由 swarm 转换后灌入。

### 3.4 扑翼

二面角按正弦在 `[dihedral_min, dihedral_max]` 间摆动；每只的 `flap_hz` 与初相都不同（整群不同步）。
大风时下限抬高（翅膀被吹得合不拢）、上限略降。停歇时向合拢值靠拢。

## 4. 天气接入

`ButterflySwarm.wind_now()` 的来源优先级：

1. **`Wind` autoload 的 `cur_dir/cur_strength/cur_gust/cur_turbulence/cur_speed`**
   —— 它才是草与植被实际用的那一份（`scripts/wind.gd` 头注释有完整依赖说明），优先它可保证两侧一致；
2. **`Weather` autoload 的 `wind` / `wind_dir` / `wind_gust` / `wind_turbulence` / `wind_speed`**；
3. **内置"微风"常量**（抄自 `Weather` 的 CLEAR 预设）—— 保证蝴蝶永远有风可用，不会静止死。

`wind_influence` 只缩放**强度类**分量，不改风向。天气还影响：雨里飞得慢、翅膀更暗更不透；
阴雨天整体压暗偏冷（`tint`）。

> 项目的 `Weather` 会自动换天气、`Wind` 每帧重算，所以蝴蝶的行为会随"变天"整体变化，不需要额外接线。

## 5. 踩坑记录（都是真机实测出来的）

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 蝴蝶**完全不可见**，代码一行报错都没有 | `Mesh.ARRAY_CUSTOM0` 必须是 `PackedByteArray`；传 `PackedFloat32Array` → `Invalid array format for surface` → **surface_count=0** | 删掉该通道（法线是常量，着色器本来就用解析式）+ 建面后自检 surface 数 |
| 2 | 清单里 20 条全 `0×0` | `detect_bbox()` 漏了 `Image` 入参分支，而 `analyze()` 传的正是 `Image` | 显式支持 `Image`/`Texture2D`/路径三种入参 |
| 3 | UV 裁剪失效、蝴蝶缩成小点 | 用 `Texture2D.get_image()` 量 bbox：导入后是 1188×804（**导入器补 2px 边**）且**四周全不透明**、抽样 19550 点不符 | bbox 一律按**原始 PNG 字节**量；导入贴图只用于 GPU 采样 |
| 4 | 生成 `.tscn` 只有一行根节点 | `PackedScene.pack()` **只序列化 `owner == root` 的节点**，而 `ResourceSaver.save()` 返回 OK | 递归设 `owner` |
| 5 | 树外每帧刷 `Node not inside tree`（600 步 1202 条） | `look_at()` 要求节点在树里 | 树外走 `Basis.looking_at(...).scaled(scale)` |
| 6 | 树外回退导致**镜像 + 掉头 180° + 缩放被抹掉** | ① 手工叉乘构出**左手系**（det=-1）② 把 +Z 对准 heading 而 `look_at` 是 **-Z** ③ 整体赋 `transform` 覆盖了缩放 | 改用 `Basis.looking_at()` + `.scaled(scale)`；并统一约定"飞行方向 = -Z" |
| 7 | 树内却报"没有天气系统"（`no_tree`） | 节点刚 `add_child`、树尚未刷新时 `get_tree()` 返回 null | `scene_tree()`：先 `is_inside_tree()` 分流，否则向 `Engine.get_main_loop()` 兜底 |
| 8 | 树外查找刷 `Parameter "data.tree" is null` | 树外调 `get_tree()` 本身就会打引擎 ERROR | 同 #7 的守卫；`_find_threat()` 也改走 `scene_tree()` |
| 9 | 蝴蝶整体偏紫红、不像素材 | 虹彩写进了 `ALBEDO`（`mix(ALBEDO, hue, …)`），而薄翅大面积处于掠射角 | 虹彩**只加进 `EMISSION`**；默认强度 0.25 |
| 10 | `alpha` 只当遮罩、不混色 | 写了 `ALPHA_SCISSOR_THRESHOLD`（材质被推进 alpha-scissor 管线），实测亮度比 1.010 | 不写它；实测真混色 0.570（= 线性 0.25 经 sRGB 的理论值 0.533） |
| 11 | `sprites` 赋值报类型错 | `Array[Texture2D]` 不接受无类型 Array | 加 `set_sprite_textures()` / `add_sprite_textures()`（内部过滤） |
| 12 | 折缝永远拍不到 | 见 §2.4：折轴被误改成 +Z（平面内自转） | 回退 +Y，并加"源码必须离开原平面"的断言 |
| 13 | 阵风下蝴蝶外溢 0.392 m | 边界用固定大小的力 | 力随超出量线性增长 |
| 14 | 两翅斜成一团、像从**背后**看 V | 折叠角符号写反（`a = +(…)·sign(x)`） | 改回 `a = −(…)·sign(x)`；并加"折向"断言（两翅 z > 0） |
| 15 | 关掉身体（`body_scale=0`）时报 `Index p_surface = 1 is out of bounds` | 仍去给不存在的 surface 1 设材质 | 设材质前先查 `mesh.get_surface_count() > 1` |
| 16 | 张翼角调 0 时翅膀变平板 | `camber` 基准角用了 `th`，`th=0` 时曲率归零 | 基准角改 `max(th, 30°)` |
| 17 | 注入到玩家面前 4 米 → 整群一出生就在逃（12 只里 10 只 FLEE） | 4 米正好落在受惊半径内 | 注入距离改 7 米 + 出生后 1.5 秒 `flee_grace` |
| 18 | `Array[Texture2D]` 的默认 UI 只能一张张加，20 张要点 20 次 | Godot 原生数组 UI 没有批量入口 | 加 `inspector_batch.gd`：在 Sprites 上方插入「全部 / 选文件… / 随机 / 清空 / 粘贴路径」 |
| 19 | 批量面板里混进一个数字就崩：`Invalid call 'String' constructor` | `String(p)` 只接受 String/StringName | `add_sprites_from_paths` 先做 `p is String or p is StringName` 类型判断（**这条是测试抓出来的**） |
| 20 | 用户重新裁剪了 PNG 后，自动裁剪范围全错、测试报"清单过期" | 清单里存的是**不透明包围盒**，换图必须重扫 | 菜单「重新扫描蝴蝶素材」；测试会拿清单与现场重扫对账（不一致即红） |
| 21 | 批量加素材后刷 `Can't get_pixel() on compressed image, sorry.` | 本项目 PNG 按 **BPTC/ETC2 压缩**导入，`get_image()` 回来的是**压缩图**，不能直接取像素 | `sample_body_color` 先 `is_compressed()` → `decompress()` → 转 RGBA8；并加测试断言"采样色 ≠ 兜底色"（只断言"返回 Color"抓不到它） |
| 22 | 批量加素材后刷 `Nonexistent function 'refresh' in base 'EditorInspector'` | 我按旧记忆写了不存在的 API | 实测把 `EditorInspector` 的 484 个方法全列了一遍：`refresh` / `update_property` **都不存在**；`EditorInterface.inspect_object()` 才是可用入口（用 `call_deferred` 调，避开 UndoRedo 事务中途重建 UI） |
| 23 | 换图后自动裁剪仍用**旧包围盒**（要重启编辑器才对） | `detect_bbox` 的缓存键是**路径** | 键改成内容指纹 `路径\|字节数\|sha256`（用 `HashingContext`，注意 `PackedByteArray` **没有** `sha256_buffer()`） |
| 24 | 蝴蝶群按**文件名**查清单取包围盒 -> 清单过期就显示错 | 裁剪框不该依赖外部缓存文件 | 改成"每张图各自算自己的裁剪框"（`BFLY_IO.compute_uv_set`）；清单只负责"素材目录有哪些图" |

## 7. 移动生态学模型（修掉"蝴蝶都是直飞的"）

### 7.1 问题与根因

用户反馈"蝴蝶现在都是直飞的"。根因不是"参数没调好"，而是**模型本身不对**：

* 旧的 CRUISE 是「随机游走（水平面）+ 朝航点直飞 + 白噪声」；
* `wander` 只更新 `x/z`（**永远在水平面里绕**），垂直方向完全没有偏置；
* 一旦朝向航点，那一段就是**激光直线**。
* 实测：平均转角 3.3°、97% 的转角 < 15°、直线度 0.50 —— 视觉上就是"直着飞"。

### 7.2 采用的模型（文献出处）

按**昆虫运动生态学**的经典模型重写；代码为本项目**按论文自行实现**（未复制任何外部源码）：

| 模型 | 出处 | 在本插件里的实现 |
| --- | --- | --- |
| **方向相关随机游走 CRW** | Kareiva & Shigesada (1983) *Analyzing insect movement as a correlated random walk*, Oecologia 56:234-238 | `_crw_turn()`：每个"决策段"以上一段航向为基准偏转；小转角为主（`turn_scale_deg` 默认 25°），另有 `turn_heavy_p`（6%）概率来一次 `turn_heavy_deg`（110°）的**重尾大转角** → "一段直、忽然拐" |
| **Lévy flight（重尾步长）** | Turchin (1998) *Quantitative Analysis of Movement* | `_levy_step()`：Pareto 重尾 `L = Lmin·(1−U)^(−1/(α−1))`，`α = levy_alpha`（默认 1.6，昆虫典型 1.5~2.0）→ 长直迁移段与短促搜索交替 |
| **区域限制搜索 ARS** | 同上（"遭遇资源后转向频率上升"是 ARS 的判据） | 感知半径内（`ars_radius_m`）有资源 → 转角尺度换成 `ars_turn_scale_deg`（55°）、速度压到 `ars_speed_scale`（0.55）→ **在花丛里打转**；离开花丛恢复直线扩散 |
| 转向/扑翼耦合的视觉参考 | UH 2022 TOG《A Practical Model for Realistic Butterfly Flight Simulation》 | 只作视觉目标参考（本插件是静态贴图 + 着色器形变，不做流固耦合） |

> 另参考开源实现 [WebGPU-Butterfly](https://github.com/conswang/WebGPU-Butterfly) 的**目标观感**，
> 未使用其代码（许可证与语言栈都不同）。

### 7.3 实测结果

| 量测 | 旧模型 | 新模型 |
| --- | --- | --- |
| CRW 平均转角（直接量 `_crw_turn()`） | — | **5.4°**（默认）／0.0°（persistence 0.99 + scale 1°）／61.7°（persistence 0 + scale 80°） |
| 真实场景平均转角（20 秒） | 3.3° | **2.36°**（大转角 10~21 次；净位移仅 7.5 m / 20 秒） |
| Lévy 步长范围 | — | **0.775 ~ 3.080 m**（重尾：最长 ≈ 4× 最短） |

> ⚠ **量测方法很重要**：**不能在全量仿真里量转角**。风拖曳每帧都在改速度方向，
> 噪声地板约 3°，把参数差异整个盖住 —— 实测 `persistence` 0.72→0.99 时平均转角
> 反而从 3.25° 变到 4.08°，看起来像"参数失效"。所以要**直接量 `_crw_turn()`**。

### 7.4 一个真实踩过的坑：高频噪声压过模型

第一版保留了旧的"高频小噪声"幅度 **0.35**。实测后果：**噪声完全主导方向**，
CRW 参数调到极端（persistence 0.99 + turn_scale 1°）平均转角反而更大。
量级分析：CRW 转向项 ≈ `3.2 × 速度差` ≈ 1.6 m/s²（速度差 0.5 m/s 时），
与 0.35 的白噪声同量级。**降到 0.08** 之后 CRW 才成为方向的主导项。

### 7.5 禁止"飞行时瞬移"

用户反馈"禁止蝴蝶飞行时瞬移"。查到一个**真实的瞬移源**：

* `BASK/DRINK` 每帧 `position = position.lerp(_perch, 0.25)`；
* 而 `_perch` 的**默认值是世界原点 (0,0,0)**，`_find_perch()` 找不到落脚点时也不会更新它；
* → 蝴蝶每次进入停歇都**朝原点以 ~15 m/s 跳过去**（实测：5 米外单帧位移 **1.25 m**）。

修法（四层）：

1. 状态机进 BASK 时先把 `_perch` 兜底成**当前位置**（找不到落脚点就原地停）；
2. 靠拢改成**限速**（`perch_speed`，默认 1.2 m/s）—— 落地过程看得见；
3. 落脚点离得太远（> `perch_rearm_distance`，默认 3 m）就**就近重置**，不长途飞；
4. `advance()` 积分后统一加一道**单帧位移上限**（`max_step_factor`，默认 1.6）：
   把**任何来源**的异常位移（边界硬夹、帧长抖动、区域被改小）降级为"快速移动"。

实测：BASK 单帧位移 **1.25 m → 0.0000 m**；900 帧最大单帧位移 0.114 m（上限 0.213 m）；
极端参数（speed_max 8 + accel 40 + wind_drag 1）下仍不超上限。

## 8. 与草（SimpleGrassTextured / sgt）的交互

### 8.1 通道选择

复用本仓库**既有的约定**（`scripts/wind.gd` 就是这么给草写风与角色倒伏的）：
> 扫场景里的草材质 → 每帧逐材质写 uniform。

**为什么不用 `global uniform`**：Godot 4.7 里运行时 global uniform 在**顶点阶段失效**
（`scripts/wind.gd` 顶部有实测记录），所以只能逐材质写。

### 8.2 两个着色器都要接（这是本仓库的真实情况）

实测主场景运行时：

| 着色器 | 材质槽数 | 说明 |
| --- | --- | --- |
| `res://assets/shaders/grass_wind.gdshader` | **274** | ★ **场景里真正渲染的那片草**（项目自制，带 `world_vertex_coords`） |
| `res://addons/simplegrasstextured/shaders/grass*.gdshader` | **6** | SGT 插件自带着色器（材质挂在 `material_override` 上） |

所以 `GRASS_SHADER_HINTS` 两个路径都认，两边都加了同一组 uniform。
（`_grass_mats` 去重后是 **7** 个共享 `ShaderMaterial` 实例 —— 正是"整片草共用少数材质"的预期结构。）

### 8.3 uniform 契约

| uniform | 类型 | 含义 |
| --- | --- | --- |
| `sgt_butterfly_pos[2]` | `vec3[2]` | 蝴蝶世界坐标（未用槽位写 1e9 = 视为无穷远） |
| `sgt_butterfly_vel[2]` | `float[2]` | 0~1 飞行快慢（越快拂得越开） |
| `sgt_butterfly_press[2]` | `float[2]` | 0~1 **贴得多低**（越高越小） |
| `sgt_butterfly_radius` | `float` | 影响半径（米） |
| `sgt_butterfly_bend` | `float` | 倒伏强度（0~3） |
| `sgt_butterfly_count` | `int` | 有效插槽数（**0 = 整段跳过，零开销**） |

**为什么只推 2 只**：着色器里每只蝴蝶都要对**每个草顶点**算一次距离，而整片草共用少数材质 ——
插槽越多，整片草的顶点开销越大。取"最贴草的 2 只"足够表现"有东西在草里动"。

**压草高度带 `grass_bend_height` 必须是 1.15 m**：蝴蝶常规飞行高度实测约
**区域底 + 1.0 m**；第一版设成 0.6 m → `press` 恒为 0、交互完全看不见。

### 8.4 三个真实 bug（都修了，都有回归测试）

| bug | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| **`MultiMeshInstance3D` 不是 `MeshInstance3D` 的子类** | 扫描静默失败：`_grass_mats` 恒为 0、压草完全失效 | 写了 `(n as MeshInstance3D).mesh`，对 MultiMesh 得到 `null`，再取 `.mesh` 报 `Invalid access to property or key 'mesh' on a base object of type 'Nil'` → **整次扫描在第一个草节点上中断** | 用共同父类 `GeometryInstance3D` 取 `material_override`，再**按实际类型**分别取 mesh（本仓库 `prop_texture_quality.gd` 也记录过同类坑） |
| **Godot 不支持 uniform 数组的默认值** | 着色器编译失败：`Setting default values to uniform arrays is not supported` | 给 `vec3[2]`/`float[2]` 写了初值 | 去掉初值，由 GDScript 每帧全部写入（含未用槽位） |
| `global_position` 在**树外**恒为 (0,0,0) | 本地 y=2.30 却报世界 y=0.00 → press 算成"贴地"、整片草被压平 | `Node3D.global_position` 依赖祖先链 | 树外时用 `global_transform * position` 手工折算 |

## 9. 参数暴露与检查器（含两个 UI/交互坑）

### 9.1 全部提到节点上（用户诉求："暴露参数到检查器面板"）

飞行行为（12 个）+ 草交互（5 个）+ 防瞬移（3 个）都已做成群组节点上的 `@export`，
并按 `@export_group` 分组显示。以前它们只在 `ButterflyTuning`（可选 Resource）里，
选中节点时**根本看不到**。

### 9.2 覆盖语义：**节点值优先于 tuning 资源**

坑：`tuning_dict()` 原来把资源合并写在**后面**，会把节点刚设的值又盖回资源里的旧值 ——
表现就是"在面板上调了没反应"。

修法：资源合并完之后，按显式清单 `GROUP_OVERRIDE_KEYS` 把节点值写回去。
清单而不是"全量覆盖"，是因为资源还要为它特有的几十个参数（能量/避难/虹彩/侧倾…）提供值；
只有"节点上也有同名导出"的键才由节点接管。
**新增节点级导出时记得把键名加进 `GROUP_OVERRIDE_KEYS`**（漏了就会重现"调了没反应"）。

### 9.3 ★ 检查器分组名里不能有 `/`

用户截图确认：`飞行行为 Flight (CRW/Lévy/ARS)` 被渲染成三层错位标题
（`飞行行为 Flight (CRW` / `Lévy` / `ARS)`）。

原因：Godot 把 `@export_group("A/B")` 里的 **`/` 当作子分组分隔符**（不是 bug，是设计）。
所以分组名改用 `·` 与空格：`"飞行行为 Flight · CRW Lévy ARS"`。

## 10. 已知边界与后续可做

* **侧视变窄是真实的**：从正侧方看蝴蝶本来就窄。要改善观感应做"限制最小侧视角"（视觉朝向随相机偏转），
  **不要**改折轴（见 §2.4）。
* 每只蝴蝶一个 `MeshInstance3D` + 独立 `ShaderMaterial`（必要：各自扑翼）。
  若要上百只，可改 `MultiMeshInstance3D`，但每实例参数需走 `INSTANCE_CUSTOM` + `ARRAY_CUSTOM0`（`PackedByteArray`，见坑 #1）。
* 避障目前是"高度带软推 + 边界硬夹"，没有逐只 raycast（60 只时每帧 raycast 成本可观，且地形碰撞体分布未知）。
  需要更精确时可注入地面高度（约定见 `butterfly.gd` 的 `_force_ground` 注释）。
* 未做：捕食者/鸟、蝴蝶之间的求偶动画、被采集/交互。
