## 1. 已修问题（症状 → 根因 → 修法）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 右键擦除对**整片草**无效（面板提示"没有实例"） | 草被归到普通 `Node` 分组下，擦除只遍历容器**直接子节点** | `world_brush_instance_scan.gd` 递归整棵子树，且**所有**子节点都下探 |
| 2 | 同上，即使能下探也擦不到 | 只认 `world_brush_instance` 元数据，而变体/脚本摆放的实例**没有**它 | 判定放宽：**是场景实例（`scene_file_path` 非空）即算**；元数据命中优先 |
| 3 | 擦完 Ctrl+Z，实例全被塞回容器根、**不在原分组** | 旧撤销一律 `container.add_child()`，不记原父节点 | 快照记 **父节点 + 位次 + 全局变换**，撤销挂回原处 |
| 4 | 拖拽擦一片后 Ctrl+Z，**只回来最后一笔** | 每笔擦除覆盖同一份快照 | 快照**累加**（整条 stroke 一条 Undo） |
| 5 | 拖动擦除撤销后**兄弟顺序变了** | 位次是"摘下当时、在剩余兄弟里的位次" | 挂回时**按摘下的逆序**（§3.2） |
| 6 | 新刷的草会**叠在**已有草上（间距失效） | 间距统计同样只扫一层 | 与擦除共用同一套递归扫描 |
| 7 | 【历史】撤销/重做**整个失效**：`undo_redo.cpp "action_level > 0"` | 旧变体工具 `_replace_node()` **先 `create_action`、后面还继续读节点属性**；中途节点被释放 → 函数中断 → 动作永远没 commit | 规则保留：动作**最后登记**，`create→commit` 之间只放 `add_*`（§3.4）。插件已删，但规则对任何写 Undo 的代码都成立 |
| 8 | 【历史】撤销后草被**立刻再随机一次**、撤销栈被塞满 | 旧变体工具监听 `node_added`，把"撤销挂回"当成"新放置" | 已改成**落点前随机**（先挑场景再 `instantiate`），没有钩子、没有第二次替换 |

## 2. 「多选 + 随机摆放」现在怎么工作

### 2.1 怎么用（编辑器里）

1. 场景行点 **Variants**（多选文件对话框，`*.tscn`，可按住 Ctrl 多选）→ 选中项 = 这个笔刷的**额外变体池**（不含行里的主场景）；
2. 点 **Weights** → 给池内每个场景填相对权重（1..999，**1 = 等概率**，不填就是全 1）；
3. 之后每次落点，从这个池里按权重随机挑一个实例化；
4. 只想用单场景：把池清掉（对话框里只选主场景，或取消）——「Weights」会自动禁用。

### 2.2 代码路径

```
点击「Variants」        dock._on_scene_variants_pressed        EditorFileDialog(FILE_MODE_OPEN_FILES)
选完                   dock._apply_scene_variants            剔掉主场景、去重 → 写进当前场景 profile
                       dock._emit_scene_variants_changed     signal scene_variants_changed
点击「Weights」        dock._on_scene_weights_pressed        每个池内场景一个 SpinBox
确定                   dock._on_scene_weights_confirmed      只存 >1 的项 → profile
                       dock._emit_scene_weights_changed      signal scene_weights_changed
插件收到               plugin._on_scene_variants_changed / _on_scene_weights_changed
每个落点               plugin._instantiate_selected_scene
                         └ _pick_stamp_scene()               池<=1 用主场景；
                              SCENE_POOL_SCRIPT.weights_for() → pick_index(rng, paths, weights)
                              └ _instantiate_scene_root(picked)   / LOD 组的 Near 层也用 picked
元数据                 instance.set_meta(SOURCE_SCENE_META, last_stamp_source_path)
```

- **主场景**仍由行里的 `EditorResourcePicker` 决定，是池的第一顺位；
- `SOURCE_SCENE_META` 记的是**这一笔实际用的那个变体**（擦除/扫描、LOD、auto-LOD 都靠它认人）；
- LOD：开了距离 LOD 时，`Near` 层 = 挑中的那个变体，分组 meta 也记它；
- auto-LOD / LOD 设置更新：匹配**整池**（不是只匹配主场景），见 `_stamp_pool_paths()`。

### 2.3 持久化与迁移

| 项 | 位置 |
|---|---|
| 变体池 | `user://world_brush_palette.cfg` → `[scene_brush_settings] profiles/<主场景路径>/random_variants`（**按来源场景**保存，与笔刷参数同一份 profile） |
| 权重 | 同一份 profile 的 `random_variant_weights`（`{场景路径: 正整数}`，**只存改过的项**；1 = 默认不存） |
| 旧的变体表 | `project.godot` 的 `[variant_tools] sets=...`（遗留数据）。首次加载时由 `dock._import_legacy_variant_sets()` 搬进各自的 profile（**只搬 profile 里还没有 `random_variants` 的**，不会覆盖新选的池），源里的"来源场景自己"会被剔掉 |

> 迁移完成后，`[variant_tools] sets=` 这一段就是死数据了；想清理可以直接删掉那一节
> （删之前确认每个笔刷的池已经落到 `user://world_brush_palette.cfg` 里）。

## 3. 关键约定（改这里之前先读）

### 3.1 「算不算要擦的实例」

| 节点 | 判定 | 说明 |
|---|---|---|
| 有 `world_brush_instance` / `world_brush_lod_group` / `world_brush_source_scene_path` 任一 | ✅ 算 | 本插件刷出来的实例 / LOD 分组 |
| **是场景实例**（`scene_file_path` 非空） | ✅ 算 | ★ 兜底：别的脚本摆放、手工归组、老版本随机化过的实例 |
| 普通 `Node` / `Node3D` 分组 | ❌ 不算，但**继续往里找** | 所以分组本身不会被右键删掉 |
| 实例内部的子网格 / 附件 | ❌ 不算 | 命中实例即**停止下探** |

> 代价：手工塞进 `WorldBrushInstances` 的**任意场景实例**也会被右键擦掉（有 Ctrl+Z 兜底）。

### 3.2 ★ 必须「逆序挂回」

快照里的 `indices` 是"**摘下当时**、在剩余兄弟里的位次"，会随兄弟被摘走而变小，**不是原始位次**：

```
原顺序 [A,B,C]，按树序逐个摘：
   摘 A (idx 0) → [B,C] → 摘 B (idx 0) → [C] → 摘 C (idx 0) → []
快照位次 = [0, 0, 0]

顺序挂回：A→[A]；B(idx 0)→[B,A]；C(idx 0)→[C,B,A]   ✗ 正好倒过来
逆序挂回：C→[C]；B(idx 0)→[B,C]；A(idx 0)→[A,B,C]   ✓ 原样
```

验收点是**最终兄弟顺序**，不是逐个 `get_index()`。

### 3.3 ★ 快照必须「累加」而不是「覆盖」

擦除是拖着鼠标一路刷的：一次 stroke 里每个 stamp 摘一批，而撤销要把**整条 stroke** 一起还原。
所以擦除走 `detach_into()`（追加），重做走 `detach_instances()`（单批）。

### 3.4 ★ UndoRedo：动作「最后登记」，create→commit 之间不许有会失败的事

**规则**：`create_action()` 到 `commit_action()` 之间只能有 `add_do_method` / `add_undo_method` /
`add_*_reference`；所有会读节点属性、`load()`、`instantiate()` 的事都放在 `create_action()` **之前**。

违反的后果（历史实测，用户报的就是这个）：

```
ERROR: res://addons/variant_tools/wb_hook.gd:142 - Invalid access to property or key 'owner' on a base object of type 'previously freed'.
ERROR: core/object/undo_redo.cpp:473 - Condition "action_level > 0" is true. Returning: ""
ERROR: core/object/undo_redo.cpp:428 - Condition "action_level > 0" is true. Returning: false
```

GDScript 运行期错误会让函数**就地中断** → 已打开的动作永远没 commit → `action_level` 卡在 `>0`
→ 此后**整个编辑器**的撤销/重做都报错。另外 `commit_action()` 的 `execute` 要传 **`false`**
（场景树已经手动改过），否则会刷一堆 "already has a parent"。

### 3.5 随机摆放语义（★ 权重只来自使用者，插件不猜）

- 池 = 主场景 + 额外变体；**池里只有 1 个 = 不随机**（普通单场景笔刷）；
- 权重缺省 **全 1 = 池内均匀随机**；面板「Weights」里改（1..999），写进场景 profile；
- **插件里没有任何按文件名/内容推断权重的代码**（本轮明确要求，并被测试哨兵盯着）：
  `world_brush_scene_pool.gd` 不读文件名、没有关键字表；它只做「按外部给的权重挑」：
  ```gdscript
  weights_for(paths, weight_map) -> Array[int]   # 缺失 = 1，非法值（<=0 / 非数字）= 1
  pick_index(rng, paths, weights) -> int          # 权重长度不符 / 总和 <=0 → 退化成均匀随机
  ```
- 挑选用插件自己的 `random_generator`（编辑器里能播种复现，测试也好写）。

> 通用性约束由 `tests/test_world_brush_scene_pool.gd` 的两条哨兵守住：
> ① 源码里不许出现模型/项目专属词；② 模块里不许有 `weight_rules` 这类硬编码表、
> 不许按文件名给权重（不读文件名）。

## 4. 踩过的坑（写代码时容易再犯）

| # | 坑 | 症状 / 报错 | 正确做法 |
|---|---|---|---|
| 1 | 拿 `EditorPlugin` 当普通类 `new()` | `Class 'EditorPlugin' can only be instantiated by editor` | 纯逻辑抽成 `RefCounted` 模块，插件只做接线（本插件已有两个这样的模块） |
| 2 | `var x := SOME_SCRIPT.static_func()` | `Parse Error: Cannot infer the type of "x" ...`，**整个插件加载失败**（编辑器里表现为插件悄悄不生效） | 调静态函数一律显式标类型：`var x: int = ...` |
| 3 | 对已释放实例做类型判断 | `Left operand of 'is' is a previously freed instance`，**整个撤销函数中断** | 先 `is_instance_valid()`，**再** `is Node3D` |
| 4 | 递归时只处理 `Node3D` 子节点 | 普通 `Node` 分组整片漏掉（bug #1 的第二层） | 所有子节点都下探，只在**判定**时看类型 |
| 5 | 快照写成覆盖 / 按原顺序挂回 | 只还原最后一笔 / 兄弟顺序乱 | §3.2、§3.3 |
| 6 | 在 `_initialize()` 里建测试节点 | `Node3D.global_position` 返回**单位变换**（还没进树）→ 半径筛选全命中 | 测试放第一帧 `_process()` 里跑 |
| 7 | 用 `--headless --editor` 自检 | **会重存被编辑的场景**：本轮实测把 `main.tscn` 的 754 个实例整棵子树写没了（264983 → 62029 字节） | 跑之前 `Copy-Item` 备份 + 记 SHA256，跑完比对；自检节点**绝不挂被编辑场景**（挂自己的临时根 / 用自定义对象当 `create_action` 的 history 目标）；只做 `--script` 解析检查最安全（不保存场景） |
| 8 | 把 `main.tscn` 只放在工作区不当备份 | 本轮该文件被**外部覆盖过两次**（内容变回 HEAD：804 节点 / 无你的删除与缩放微调） | `.runtime/main_good_backup.tscn` 是逐字节正确的备份（264983 字节 / SHA256 `1B8BD24D…`）；建议尽快 `git commit` 把当前状态固定下来 |

### 5.2 现场探针

`.runtime/probe_wb_erase.gd`：只 `instantiate()`、**不入树**，不跑游戏逻辑、自己不写文件。期望输出：

```
container=WorldBrushInstances direct_children=1
NEW scan candidates = 754      ← 修好之后：整片草都能擦
OLD algorithm       = 0        ← 修之前：一个都擦不动
其中带 world_brush_instance 元数据的 = 0
其中嵌在分组里（非容器直接子节点）的 = 754
```

- `NEW scan candidates` = 0 → 容器路径没找到（`_find_world_brush_container` 只认**场景根的直接子节点**，§6 第 1 条）；
- 数字和肉眼数的不一致 → 先看 `direct_children`，多半是结构又变了。

### 5.3 编辑器里怎么看

- 插件是否加载：输出面板搜 `World Brush: Plugin enabled successfully.`（加载失败会先打 `SCRIPT ERROR`）；
- 擦除：停靠面板状态栏 `Erased In Stroke: N`；一条都没擦到会显示 `Erase Brush — No Instances Here`；
- 随机摆放：每行按钮显示 `Variants N`（N = 池里场景数，含主场景）；切场景会打
  `World Brush: Selected scene -> … | variants K`，改池会打 `World Brush: Variant pool -> …`；
- 擦不动时先看提示：`No Valid Surface` / `No Surface Under Cursor`（光标下没表面，与实例判定无关）、
  `No World Brush Instances`（找不到容器，§6 第 1 条）、`Erase Brush — No Instances Here`（容器在、半径内没实例）。

### 5.4 见到 `action_level > 0` 怎么办

**含义**：某个 UndoRedo 历史里有一个**打开了却没 commit 的动作**，这条历史上的撤销/重做全被拒。

1. 报错**之前**那条才是根因 —— 往上找第一条 `SCRIPT ERROR` / `...previously freed...`；
2. 看那个函数 `create_action(` 到 `commit_action(` 之间有没有会失败的语句 → 按 §3.4 挪到 `create_action` 之前；
3. `commit_action()` 一律传 `false`；
4. **临时自救**：保存场景 → 重开编辑器（`action_level` 是内存态，重启即清空）。

## 6. 已知残留与边界

| # | 项 | 现状 | 影响 |
|---|---|---|---|
| 1 | 容器必须挂在被编辑场景根的**直接子节点** | `_find_world_brush_container()` 只扫一层 | 把 `WorldBrushInstances` 挪到更深层 → **绘制和擦除都会提示** `No World Brush Instances`（同类型盲区，未夹带修） |
| 2 | 擦除半径只看**水平**距离（XZ） | 与绘制间距同一套语义 | 巨大树冠离树干原点太远时，点在树冠边缘擦不到；点根部正常 |
| 3 | 空分组不会自动清理 | 擦光一个分组里的草后分组仍在 | 预期行为（分组是用户的组织结构） |
| 4 | 判定放宽的副作用 | 容器里的**任意场景实例**都算可擦 | 手工摆放的实例也会被右键擦掉 → Ctrl+Z 兜底 |
| 5 | 池里加载失败的场景 | `_refresh_stamp_scene_pool()` 静默跳过 | 池变小但不报错；可看输出面板的 `stamp pool N` |
| 6 | 随机 + 距离 LOD 同时用 | LOD 组以"挑中的变体"为 `Near` 层，组 meta 记它 | LOD 设置更新按整池匹配；关掉 LOD 更简单 |
| 7 | `main.tscn` 曾被外部覆盖两次 | 已用 `.runtime/main_good_backup.tscn` 逐字节恢复（802 节点 / 754 嵌套 / 你之前那两处改动都在） | **建议尽快 commit**，别再让它处于"只有工作区一份"的状态 |
