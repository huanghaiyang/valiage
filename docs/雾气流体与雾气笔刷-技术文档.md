# 雾气流体与雾气笔刷 · 技术文档

> 目标：在 Cozy Vale 里做出**会被风推着走**的雾 —— 不是滚动噪声贴图，而是真的解
> 不可压纳维-斯托克斯方程得到速度场，再用它输运一层雾浓度；同时提供一个编辑器插件，
> 让美术直接在 3D 视口里把雾刷出来，刷出来的形状还会继续被流体吹动。

## 2. 方程与离散格式

不可压 NS + 被动标量（雾浓度 d）：

```
∂u/∂t = -(u·∇)u - ∇p + ν∇²u + f ,   ∇·u = 0
∂d/∂t = -(u·∇)d - σd + κ(base - d) + S
```

解法是 **算子分裂 + 半拉格朗日（Stam, *Stable Fluids*, 1999）**：

| 步 | 做什么 | 对应通道 |
| --- | --- | --- |
| ① | 加力：均匀风（朝目标速度松弛）+ 最多 8 个高斯源（热源/法术/笔刷吹风） | `ns_advect_velocity` |
| ② | 速度半拉格朗日自输运 + 耗散 | `ns_advect_velocity` |
| ③ | 涡量 ω = ∂v/∂x − ∂u/∂y | `ns_curl` |
| ④ | 涡量约束力 F = ε·(N × ω)，补回数值耗散抹掉的小涡 | `ns_vorticity` |
| ⑤ | 散度 div = −½h(∂u/∂x + ∂v/∂y) | `ns_divergence` |
| ⑥ | 压力泊松 ∇²p = div，逐趟迭代（Gauss–Seidel 式就地 Jacobi） | `ns_jacobi_1..N` |
| ⑦ | 减梯度 u ← u − ∇p（投影完成，得到无散度速度） | `ns_gradient` |
| ⑧ | 浓度输运 + 耗散 + 向画笔底图松弛 + 源注入 | `ns_advect_density` |
| ⑨ | 合成：轻量平滑压掉格子感，与底图取 max | `ns_composite` |

**单位约定（最容易写错的地方）**：速度是**域单位/秒**（1.0 = 每秒横穿整个域一次）。
半拉格朗日回 trace 的单元偏移 = `速度 × dt × N`；散度里的 `h = 1/N`。少乘或多乘一个 `N`
的表现是"雾几乎不动"或"雾飞快且怎么调风都没用"——`tests/test_fog_ns_reference.gd` 里有一条
专门的单位哨兵用例（风 0.2、吹 1 秒 → 重心必须移动 ≈0.2 个域宽）。

**边界是周期的**（邻域下标环绕），不是固壁。原因很实在：闭盒 + 不可压约束**禁止净流动**，
压力投影会把风给的速度几乎全部抵消（GPU 端实测：目标 0.15 域单位/秒的风只剩 0.0015，
雾基本不动）；周期域上离散散度自动求和为 0，压力泊松的相容性天然满足，投影质量也更好。
代价是"局部浓雾飘出去会从对面回来"，由底图松弛（`base_relax`）把形状锚住。

**上边界/地面**：求解器是 2D 水平场（成本与垂直分层无关），雾层厚度由渲染侧的竖向剖面
（`height_power`）表现；没有垂直速度，所以不存在"雾被吸到天上"这类问题。

## 3. 为什么 GPU 用 SubViewport 片元通道，而不是 RenderingDevice compute

这是本机实测的结论，不是偏好（`tools/fog_gpu_verify.tscn` 就是为验证它写的）：

| 方案 | 实测结果 |
| --- | --- |
| 本地 `RenderingDevice` + compute | 能派发、能回读，但**纹理交不进 `Texture2DRD`**（引擎报 `texture_is_valid` 失败），结果上不了屏 |
| 主 `RenderingDevice` | 被引擎禁止手动提交：`Only local devices can submit and sync.` |
| compute + 每帧 CPU 回读再上传 | 可行，但每帧一次 GPU 同步 + 上传，对"每帧都在跑"的雾气不可接受 |
| **SubViewport 片元通道**（采用） | 结果本身就是渲染器纹理，可被材质/粒子直接采样，零回读 |

**环形通道链**是这套实现的关键设计：链的末尾接回开头 ——
`advect_velocity` 读上一帧的 `gradient`、`advect_density` 读上一帧的 `composite`、
第 1 趟压力迭代读上一帧的最后一趟（跨帧热启动）。好处：

1. 每个通道写自己的专用 SubViewport，**不存在"读自己正在写的纹理"**（未定义行为）；
2. 源纹理全帧固定，材质 uniform 只需在 `setup()` 连一次；
3. 通道按节点树顺序渲染 ⇒ 后一趟看到本帧前一趟的结果；
4. 压力天然跨帧热启动，等于白拿几十次迭代的效果。

通道总数 = **7 + `jacobi_passes`**（`jacobi_passes` 默认 8 → 15 个通道）。
`FogField.enabled = false` 时全部通道设成 `UPDATE_DISABLED`，不花 GPU。

## 4. 参数速查

### 4.1 FogField（场景里那个节点）

| 参数 | 含义 / 调整效果 |
| --- | --- |
| `domain_size` | 雾气域的水平尺寸（米）。只影响世界映射，不影响模拟成本 |
| `box_height` | 雾层厚度（米）。越大雾越"厚" |
| `base_height` | 相对本节点的高度偏移；拖动节点可整体挪动雾层 |
| `resolution` | 模拟网格边长。96 是画质/开销折中；≤64 会看出格子感（靠 `smooth_weight` 压） |
| `jacobi_passes` | 每帧压力迭代趟数。越大投影越干净、越贵 |
| `fog_opacity` / `density_gain` | 整体不透明度 / 浓度放大。看不到雾先查这两个 |
| `composite_base_floor` | **底图地板**强度（0..1）：1 = 旧行为（合成时 `浓度 = max(模拟, 底图×增益)`）；0 = 底图只当吸引子。**角色/法术的挖雾与涡流完全看不出效果时调 0**（见 §7 最后一行） |
| `height_power` | 竖向衰减指数。1.0 线性、2~3 更像"贴地晨雾" |
| `wisp_amount` | 絮状扰动强度，打散"一块饼"的观感 |
| `velocity_dissipation` | 速度耗散（每秒比例）。风停后流场安静下来的速度 |
| `density_dissipation` | 雾自然消散速度 |
| `vorticity_strength` | 涡量约束强度，0 = 关闭（雾会更快糊成一团） |
| `base_relax` | 向画笔底图松弛的速率（1/秒）。**画笔与流体统一的开关**：0 = 刷出来的雾会被彻底吹散 |
| `auto_weather` | 跟随 `/root/Weather` 的 `wind` / `fog` 与风向 |
| `wind_speed_mps` | `weather.wind = 1.0` 对应的风速（m/s） |
| `idle_opacity` | 晴天底雾不透明度（保证 Clear 天气也有一层薄地雾） |
| `character_stir_enabled` | **角色涡流总开关**。开 = 自动给 `character_group` 里**正在移动**的节点注入绕身环流（静止不注入） |
| `character_group` | 扫哪个组找角色（默认 `player`，见 `player.gd` 的 `add_to_group`） |
| `character_swirl_mps` | 绕身**切向风速**（m/s）：正负 = 旋向，0 = 只推开不转（旧观感）。10~20 自然、30~45 明显 |
| `character_swirl_radius_m` | 涡流半径（米）：3~4 贴着人绕，5~8 整个人带起一团 |
| `character_carve` | 角色周围挖雾速率（每秒）：负值挖出可见的洞；0 = 只搅不挖 |
| `character_swirl_ref_speed` | 涡流强度的参考速度（m/s）：角色速度/本值 缩放切向速度，夹在 0.25~1.6 倍 |

### 4.2 运行时接口

```gdscript
# 世界某处的雾源（篝火/角色/法术）。velocity_world 是"这片区域的目标风速"，不是冲量。
# 想让源持续起效请每帧调用（只影响当帧）。
# 后两个可选参数：radial_speed = 径向排开（推开介质）、swirl_speed = 绕心切向（涡流）。
field.add_source(world_position, radius_m, density_rate, velocity_world,
        Vector2.ZERO, radial_speed, swirl_speed)

# 只投一个涡（不挖雾、不排开、纯旋转）：在 pos 周围卷起半径 4 米、切向 8 m/s 的涡
field.add_vortex(world_position, 4.0, 8.0)

field.set_wind_mps(Vector2(3.0, 1.0))   # 直接指定风（m/s），会接管天气的风
field.clear_wind_override()             # 交还给天气
field.set_fog_opacity(1.6)              # 覆盖天气推导出的不透明度；负数恢复
field.apply_quality(2)                  # 0低/1中/2高/3极高：分辨率+迭代+粒子数
field.density_texture() / velocity_texture()   # 给其它特效复用流场
```

### 4.3 角色涡流（人跑过、雾绕着转）

**它是什么**：速度场里原来只有两种注入 —— "沿运动方向拖拽"和"径向排开"，都是平移，
所以物体穿过雾只会把雾挤开，不会**卷**。角色涡流给目标速度再叠加一个**绕源中心的切向
分量**（`splat_swirl`，见 `ns_advect_velocity.gdshader`）；浓度是被动标量，会被这个环流
**自然卷成螺旋**并拖在身后的轨迹上，不需要新增管线/通道，也不占额外的源配额。

**怎么接**（两条路，二者互斥不会重复注入）：

| 方式 | 用法 | 适用 |
| --- | --- | --- |
| 自动（默认） | 角色在 `character_group`（默认 `player`）里即可，调 `character_swirl_mps` 等参数 | 本项目角色：**开箱即有** |
| 显式组件 | 在物体上挂 `FogInteractor`，调它的 `vortex_spin_mps` | 道具/法术/雪犁等只需要局部生效的东西 |

- **只在移动时注入**：速度 < 0.05 m/s 直接跳过 ⇒ 站着不动时观感与旧版一致。
- **强度随速度缩放**：`character_swirl_mps × clamp(速度 / character_swirl_ref_speed, 0.25, 1.6)`。
- **单位是 m/s**（不是"域单位/秒"）：域尺寸改了，同一个数在屏幕上表现一致。
- `FogInteractor.vortex_spin_mps = 0`（默认）以及 `character_swirl_mps = 0` 时，
  着色器里整块被跳过 ⇒ **逐字等于旧行为**。
- **在哪调**：这 6 个参数在 **FogField 节点的检查器**里，也在 **Fog Brush 面板新增的
  「── 角色涡流（走动时绕身卷起）──」一节**里（两处同名同值；面板那一份方便在编辑器里
  连刷边调）。`FogInteractor.vortex_spin_mps` 在它自己节点的检查器里（它属于组件，
  不属于 FogField，面板不代管）。`tools/fog_check_scripts.tscn` 有两条哨兵守着这件事：
  新属性必须带 `PROPERTY_USAGE_EDITOR` 出现在脚本导出表里（= 检查器里可见），
  面板上必须真的建出这 6 个旋钮。

**实测标定**（`tools/fog_vortex_showcase.tscn` 的自检数值，70 米域 + 默认求解器参数）：
`character_swirl_mps = 20` ⇒ 角色周围实测环流 **≈ +2.5 ~ +4.6 m/s**，旋向与参数同号；
关闭时为 ~0.03 域单位/秒（只剩尾涡）。想更明显就调到 30~45。

**看得见的前提（重要 · 实测踩过三轮）**：涡流/挖雾改的是**浓度**，所以要让它在画面上看得见，
四道锁必须同时松开 —— 缺任何一道都表现为"改了参数完全没效果"：

| 锁 | 默认值 | 为什么锁住 | 怎么松 |
| --- | --- | --- | --- |
| ① 底图是**硬地板** | `composite_base_floor = 1` | 合成通道 `浓度 = max(模拟, 底图×增益)`，底图刷成 1 就永远降不下来 | 调 **0** |
| ② 吸附目标**饱和** | `density_gain = 5.0`（× 底图 1.0 = 目标 5） | 浓度被 `clamp(…,0,1)` 钉在 1，挖雾源被夹在 −1.0/秒，打不过松弛的 +2.4/秒 | `density_gain` 调到 **0.6~1.0**（等价：把底图刷到 0.3~0.6） |
| ③ 吸附**愈合太快** | `base_relax = 0.6`（1/秒） | 角色挖开的洞、卷出的螺旋会在 **1~2 秒**内被拽回笔迹形状 —— **走路时几乎看不到轨迹** | `base_relax` 调到 **0.15**（0 = 不吸附） |
| ④ 浓度**散得太快** | `density_dissipation = 0.10` | 轨迹很快淡掉 | 调到 **0.05** |

四道都松开后的实测（真 `main.tscn` + 真 Player + 游戏自己的机位）：
- **原地持续注入 3 秒**：角色脚下浓度 0.439 → 0.000，屏幕像素差 42%（>8 级的像素占 42.4%）。
- **走路 5 秒**（carve −1.2 / swirl 40 / relax 0.15）：脚下 0.463 → **0.000**、身后 6 米 **0.058**、
  未经过的侧方 0.181 ⇒ 身后留下一条明显变稀的轨迹；对照（carve=0）三个点都是 0.463。
- 反过来，只要①或②还锁着：`carve = −1.4` 时角色脚下浓度仍 **1.000**、渲染 alpha **1.000**，
  屏幕上纹丝不动（这就是"没有任何效果"的真相）。

`base_relax` / `density_dissipation` / `composite_base_floor` / `density_gain` 都在
Fog Brush 面板的雾气参数一节里（后两者原先只能在检查器里改，已一并挪到面板）。

### 4.4 角色涡流「可视化」层（雾饱和时唯一看得见的做法）

**为什么必须有这一层**：浓雾场景里浓度早就饱和了（渲染出来是**不透明度 ≈ 1 的白幕**）。
白幕上**没有细节可看** —— 把浓度场搅得再厉害，屏幕上也是纹丝不动。
（实测：`carve = −1.4` 时角色脚下浓度确实降到 0，但整片雾依然全白 ⇒ 看不见。
这正是"改了参数没效果"的真相：不是没注入，是**没有对比度**。）

所以涡流不再依赖浓度场，而是**单独一层着色器**直接画出来：

| | |
| --- | --- |
| 着色器 | `assets/shaders/fog_vortex_swirl.gdshader` |
| 几何 | 角色周身一个开口圆筒（半径/高度由 FogField 每帧同步） |
| 图案 | 极坐标螺旋条带 `phase = θ + 旋向·圈数·r + 高度项 − 时间·转速`（外加 sin-hash 抖动打散规则感） |
| **明暗变化** | 暗带 → 把**浓白雾**压成灰蓝条纹（白幕上靠它显形）；亮带 → 在**深色草地/地面**上提亮（像被光扫过） |
| 渲染模式 | `depth_test_disabled` + `render_priority = 1`：必须画在体积雾与**草叶之上** —— 开深度测试时它会被草的 alpha 裁剪切成一片麻点（实测） |
| 驱动 | `FogField._stir_characters()`：强度 = `clamp(角色速度 / character_swirl_ref_speed, 0.15, 1.6)`，旋向 = `sign(character_swirl_mps)`；**角色静止 ⇒ strength = 0 ⇒ 整层全透明**（等于没开） |

参数（检查器 + Fog Brush 面板都有，见 §4.1 / 面板「涡流可视化」一节）：
`vortex_visual_enabled`（开关）、`vortex_visual_alpha`（最大不透明度 0.3~0.6 自然）、
`vortex_visual_turns`（1~2 像一股风）、`vortex_visual_spin_speed`、`vortex_visual_height_m`、
`vortex_visual_radius_m`（0 = 跟随 `character_swirl_radius_m`）、`vortex_visual_sharpness`、
`vortex_visual_wobble`、`vortex_visual_dark` / `vortex_visual_light`（暗带/亮带颜色）。

> **两种手段的关系**：`character_*`（切向注入）改的是**流体本身**，只有在雾**半透明**时
> （`composite_base_floor = 0` 且吸附增益不饱和）才看得见浓度扰动；
> `vortex_visual_*` 是**纯渲染层**，与雾的浓淡、与流体状态都无关，**浓白幕上照样看得见**。
> 要"看得见"就用后者；要"物理上真的把雾卷动"用前者（并把雾调成半透明）。

**尺寸：半径与高度是两把独立的尺子（任意值都成立）**

| 项 | 约定 |
| --- | --- |
| `vortex_visual_radius_m` | 围多大一圈（米）。**只在角色周身一点点空间**，1~2 米足够，别设大。0 = 自动取 `character_swirl_radius_m × 0.25` 夹到 0.8~2.0 |
| `vortex_visual_height_m` | 这层有多高（米）。**任意值，与半径没有任何关系**（不做计算、不按比例推导）：0.5 = 贴地一圈，2.6 = 裹住身体，5 = 卷得比人高 |
| 实现 | 着色器内部一律按 `r / radius`、`y / height` **归一化** ⇒ 半径 1.5×高 2.6 与 半径 3×高 5 看到的是**同一个图案**，只是大小不同；**也不存在"高度必须够大"** |

**"半径调小就不显示 / 半径 1 也没效果"的真正根因（已修）**：

这一层是**壳**（圆筒表面），网格恒为"半径 1、高 1"的单位圆筒、靠节点 `scale` 缩放 ⇒
壳上每个片元的 `length(v_local.xz)` **恒等于 1**。而我最初在壳面做了**径向淡出**：

```glsl
float radial = smoothstep(inner, ..., r) * (1.0 - smoothstep(0.85, 1.0, r));   // r ≡ 1 时右边恒为 0
```

⇒ 只要 `r` 落到 1，**ALPHA 恒为 0，整层完全不画**。`r` 的算法一变，可见的半径区间就跟着变：

| `r` 的写法 | 半径 0.2 | 半径 1.0 | 半径 2.0 | 半径 6.0 |
| --- | --- | --- | --- | --- |
| `length(v_local.xz) / radius`（最初） | r=5→夹到 1 ⇒ **不显示** | r=1 ⇒ **不显示** | r=0.5 ⇒ 能显示 | r=0.167 ⇒ 很淡 |
| `length(v_local.xz)`（中间那版"修"） | r≡1 ⇒ **不显示** | r≡1 ⇒ **不显示** | r≡1 ⇒ **不显示** | r≡1 ⇒ **不显示** |

**修法**：**壳面不做任何径向淡出**（壳本来就在 r=1 的表面上，径向收口没有意义），
图案只由 `角度 θ + 归一化高度 y` 决定，做成一条螺旋带
（`phase = θ + 旋向 · turns · TAU · y − 时间 · 转速`），只保留上下端淡出。
半径、高度就退化成纯粹的**世界尺寸**，与图案、与可见性完全无关。

**验证方式也必须改**：早期我拿"跨运行的两张截图做像素差"，草在摇、角色在动，
噪声本身就有几个百分点 ⇒ **把噪声当成了效果**（对照组 alpha=0 同样"有变化"就说明测法脏）。
现在的永久验证工具 `tools/fog_vortex_swirl_verify.tscn` 改成：
同一次运行、固定机位、**等间隔帧**读像素，并且**带一个 alpha=0 的对照组**
（对照组必须"无信号"才算通过），判定口径 = 信号均值 > max(噪声底×3, 0.30)。

实测（真主场景、真 Player、游戏机位；均值/命中率都是 480×360 读回像素）：

| 用例 | 信号均值 | 命中率 | 信号/噪声 | 判定 |
| --- | --- | --- | --- | --- |
| 对照 alpha=0（预期无信号） | 0.56 | 1.3 % | 1.2 倍 | ✅ 无信号（测法干净） |
| 半径 0.5 × 高 2.6 | 5.09 | 6.7 % | 12 倍 | ✅ |
| **半径 1.0 × 高 2.6** | **9.59** | **13.1 %** | **21 倍** | ✅ |
| 半径 1.5 × 高 2.6 | 16.78 | 21.6 % | 47 倍 | ✅ |
| 半径 3.0 × 高 2.6 | 50.06 | 69.7 % | 133 倍 | ✅ |
| 半径 6.0 × 高 2.6 | 14.57 | 14.3 % | 43 倍 | ✅ |
| 半径 1.5 × **高 0.5** | 4.00 | 5.5 % | 6.4 倍 | ✅（高度任意值都成立） |
| 半径 0.2 × 高 2.6 | 2.80 | 3.6 % | 3.5 倍 | ⚠️ 偏弱：壳缩在角色身体里，只剩边缘露出来 |

顺带把条纹对比度也修了：原来 `pow(wave, 2)` 的平均值只有 ~0.35，乘 `alpha_max 0.55`
后实际不透明度不到 0.2 ⇒ 浓白雾上"几乎看不见"。现在用 `smoothstep` 削成**实心丝 + 干净缝**
（丝芯吃满 `alpha_max` 0.62、缝隙归零）。

> ⚠️ **半径建议 0.5~3 米**：< 0.5 米时壳会**缩进角色身体里**（只剩边缘，信号 3.5 倍），
> 贴身常用 **1.0~1.5 米**；想要它罩住周围一圈就 **2~3 米**。

**"半径 0.2 米时把角色挡住了"的原因与修法（已修）**

| 环节 | 说明 |
| --- | --- |
| 为什么会挡人 | 这一层用 `depth_test_disabled`（当初是为了不被上千片草叶逐像素剪成麻点），代价是它**永远画在所有东西之上 —— 包括角色本人**。半径 ≥ 0.5 米时壳在角色轮廓外，看到的是"围着他的一圈风"；半径 0.2 米时 0.4 米直径的壳**整个在身体里**，条纹糊满全身 ⇒ 把人挡住 |
| 修法 | 用**屏幕深度做软遮挡**：`depth_tex : hint_depth_texture` 取场景深度，本片元比最近的不透明表面还远 ⇒ `smoothstep(0, occlusion_soft_m, 场景深度 − 本片元深度)` 柔和淡出（默认过渡 0.35 米）。**不是硬深度测试**，所以不会被草切成麻点，只会让壳在草/角色/墓碑/地面后面柔和隐没 |
| 效果 | 半径 0.2 米时壳整体被身体挡住 ⇒ **看不见，但不再糊人**（实测"角色所在中央区域差异 0.67 vs 噪声 0.68"）；半径 ≥ 1 米时环绕效果照旧（信号 8~33，信号/噪声 8~41 倍） |
| 附带代价 | 软遮挡是"物理正确"的：**贴地太矮**的壳（如高度 0.5 米）会被草挡住 ⇒ 想让涡流露出来，高度取 **≥1.5 米** |

验证工具为此加了两条判定：`半径0.2（壳在身体里，应不可见且不糊人）` —— 同时要求"无信号"
**且**"角色所在画面中央区域差异 ≈ 噪声"；以及 `半径1.5 × 高0.5（贴地在草里，预期被遮挡）`
—— 把已知的边界行为也固化成断言。

## 5. 雾气笔刷插件（addons/fog_brush）

**启用**：`project.godot` 的 `[editor_plugins]` 已登记。首次需要**重启编辑器**
（或在 项目 → 项目设置 → 插件 里勾选 Fog Brush）才会加载 —— 编辑器不会为外部改动热加载插件列表。

**用法**

1. 选中场景里的 `FogField`（没有就点面板的 **应用到雾气场** 自动创建一个）
2. 勾选 **启用雾气笔刷**，在 3D 视口里：

| 操作 | 效果 |
| --- | --- |
| 左键拖动 | 按当前模式刷（加雾 / 擦雾 / 抹平） |
| 右键拖动 | 临时切到"擦雾" |
| Shift / Alt / Ctrl + 拖动 | 让位给编辑器（旋转/平移视图），不会误刷 |
| `[` / `]` | 缩小 / 放大笔刷半径 |
| 清空 / 铺满 | 整张底图清零 / 填满（都可撤销） |
| 导出 / 导入 PNG | 与外部工具互通；PNG 是灰度图，R 通道即浓度 |

**数据流**：面板参数 → 插件把落点换算成网格坐标 → `FogBrushField.apply_stroke()`
（纯函数，带笔画插值，快速拖动不留断点）→ 落笔结束写 PNG
（`res://assets/fog/<场景名>_fog.png`，便于版本管理）+ 记一个撤销动作 →
`FogField.refresh_brush_texture()` 上传给求解器 → 运行时它成为浓度方程的**吸引子**。

**编辑器里能立刻看到雾（@tool 双路径）**：`FogField` 是 `@tool`，但编辑器与运行期走
**两条不同的装配路径**：

| | 编辑器 | 运行期 |
| --- | --- | --- |
| 求解器（13 个 SubViewport） | **不建** | 建 |
| 粒子 | **不建** | 建 |
| 体积雾网格 | 建（当**画笔静态预览**） | 建（效果本体） |
| 底图来源 | 画笔数据 → `ImageTexture` 直接喂材质 | 画笔数据 → 求解器当吸引子 |

于是在编辑器里**刷完一笔立刻能看到雾的形状**（不用按 F6），但不会在编辑器里长期跑
GPU 流体链；按 F6 运行时同一块底图会开始被风推着流动。

> ⚠️ `FogField` **必须**是 `@tool`。否则编辑器里它只是**占位实例**（placeholder
> instance）：脚本成员一概不可访问，插件一碰就报
> `Invalid access to property 'solver'` / `Attempt to call a method on a placeholder
> instance`。同时所有公开方法都要容忍 `solver == null`（编辑器路径下它就是 null）。

**为什么刷出来的雾会动**：底图不直接参与输运，而是浓度方程里的松弛项
`d += (base·gain − d)·relax·dt`。风把浓度吹变形、耗散让它变淡，松弛又把它慢慢拉回刷出来的
形状 —— 于是雾看起来是"被风吹着的活雾"，而不是一层固定贴图。

## 7. 已修问题与排障

| 症状 | 根因 | 处理 |
| --- | --- | --- |
| 雾完全不动、怎么调风都没用 | 速度被当成"单元/秒"实现（少乘 N），或用了**固壁**边界（闭盒禁止净流动） | 单位按"域单位/秒"实现；边界改**周期**（见 §2） |
| 雾变成一堆孤立方块、一输运就掉质量 | 高斯核半径用 UV 值去比单元距离（σ² 小 4 个数量级） | `_splat_into` 先把半径换算成单元数 |
| 笔刷落点与预览差半格、高斯核左右不对称 | 高斯中心少减了 0.5（UV→单元坐标约定不一致） | 统一用 `uv_to_cell()` 的约定 |
| 投影"迭代 2 次和 40 次结果一模一样" | 统计散度时把贴壁那圈算进去了（那圈由边界条件决定），固壁版本才会这样 | 改周期边界后全域可统计；`max_divergence()` 不再需要 margin |
| 压力链报"通道 jacobi_1 的源 jacobi_6 不存在" | `_chain_names()` 用了 `range(N)`（得到 jacobi_0..N-1）而接线用 1..N | 统一从 1 开始编号 |
| 着色器编译失败：`Unknown identifier 'SCREEN_UV'` | 在 `.gdshaderinc` 的**函数里**直接用了带 stage 限定的内建量 | 内建量由调用方当参数传进去（`ns_cell(SCREEN_UV)`） |
| 粒子刷屏报 `No compute pipeline was set` | 粒子 process 着色器里给只读的 `LIFETIME` 赋值 → 编译失败 → 粒子系统照样派发 compute | 不写 `LIFETIME`；逐粒子寿命用 `CUSTOM.y` 折算 |
| 粒子着色器 `No matching function found: rand_from_seed` | Godot 4.7 粒子着色器没有该重载 | 用自带的 sin-hash 逐粒子伪随机 |
| "热源完全没反应" | 速度源把力乘上了 `splats[i].w`（浓度分量），只推速度时 w=0 → 力被乘成 0 | 速度用独立数组：`xy`=目标速度、`z`=松弛率（目标速度语义） |
| 编辑器里"刷了但运行时没有" | 底图没有推给求解器 / 没有落盘 | 落笔结束强制 `refresh_brush_texture()` + `save_to_png()`（测试里有接线哨兵） |
| 编辑器报 `Invalid access to property 'solver'`、`Attempt to call a method on a placeholder instance` | `FogField` 不是 `@tool`：编辑器里脚本没被实例化，插件拿不到任何脚本成员 | ① `fog_field.gd`/`fog_brush_field.gd` 加 `@tool`；② 编辑器路径只建体积雾预览、不建求解器；③ 插件改走 `FogField.add_brush_velocity()`，所有公开方法容忍 `solver == null`（回归用例 `test_fog_field_editor_path_is_safe`） |
| 编辑器预览是一整块**实心雾**（明明没刷过） | 未赋值的 `sampler2D` 在 Godot 里会绑到一张白图，`density = 1.0` | 空底图时把 `density_gain` 压到 0（预览即空场景），有底图再恢复 |
| 清单里某个 `.gd` 报 `cannot instantiate — abstract or broken`，但 `find_symbols` 能列出全部函数 | 测试套件是 `RefCounted` 系（**不是 Node**），误用 `add_child()` 之类 Node API 会解析失败 | 修掉 Node API 调用；必要时 `filesystem_manage(scan)` 后重跑（发现缓存 #882） |
| 刚存出去的 PNG 立刻读不回来 | `load_from_png` 用 `ResourceLoader.exists`（只认导入过的 res:// 资源） | 改用 `FileAccess.file_exists` |
| 插件报 `Cannot assign a new value to a constant` | `Node3D.global_scale` 对脚本**只读** | 用 `scale`（预览节点挂在未缩放的父节点下） |
| 插件报 `Identifier "selection_changed" not declared` | `EditorPlugin` 没有这个信号 | 从 `EditorInterface.get_selection()` 拿到的对象上连 |
| 面板脚本改完，"面板空白/插件加载失败" | 手搓 UI 的 API 写错，而编辑器里只看到一句泛泛的失败 | `tools/fog_check_scripts.tscn` 会**真的实例化面板**并检查控件与信号 |
| 端到端自检"风没推动雾" | `await process_frame` 等的是帧数，编辑器里启动的游戏常跑几百帧/秒，60 帧只有 0.2 秒模拟时间 | 依赖模拟时间的断言改用 `create_timer(秒)` |
| **角色在雾里走，雾完全不被扰动**（"涡流/挖雾没效果"） | **不是没注入**：分组与注入实测都正常（`player` 组 1 个成员、`_characters=1`、角色周围切向速度实测 +9~10 m/s）。真正原因是**浓雾饱和成白幕 ⇒ 没有对比度**：浓度被 `clamp(…,0,1)` 钉在 1、渲染 alpha ≈ 1，任何扰动都改变不了画面（实测 `carve = −1.4` 时角色脚下浓度 1.000→0，屏幕纹丝不动） | 用**涡流可视化层**（§4.4，`vortex_visual_*`）：独立着色器直接画螺旋明暗条带，不依赖浓度 ⇒ 浓白幕上照样看得见，且**不需要改动雾的量感**（本轮就是这样落地并出图的）。若确实要"物理上把雾卷动"，再走另一条路：`composite_base_floor = 0` + 吸附增益别饱和 + `base_relax` 调小，代价是雾会整体变薄（实测均值浓度 1.0 → 0.19~0.58，按 `base_relax`/`density_gain` 而定） |
| 雾气里出现**扇形硬折痕**（沿盒子棱边投影线的直线折角），薄地面雾侧看最明显；同一参数下还会"某些视角浓、某些视角整片没有" | 体积雾盒用了 `cull_disabled` ⇒ 每个像素被**正面 + 背面两个片元各混合一次**：① 雾被混合两次（浓度≈翻倍，且"混合几次"随遮挡变化）；② `camera_soft` 用的是**片元自己的世界坐标**，正/背面到相机的距离差一个盒子直径 ⇒ 一个像素的结果取决于"它被哪几个面覆盖"，而"面的集合"只在盒子棱边的投影线上变化 | `fog_mist_volume.gdshader` 改 `cull_front`（只画远壁）+ `depth_test_disabled`：**每像素恰好一个片元**，遮挡交给着色器用 `depth_tex` 逐步裁剪（`partial`/`depth_soft`/`edge_soft_m`）。副作用：原先被混合两次的地方浓度≈减半（单次散射才是对的）、原先被深度测试整块剔掉的视角现在有雾了 —— 需要时用 `fog_opacity` / `density_gain` 回调 |

**性能提示**

- 关掉整个系统：`FogField.enabled = false`（通道转 `UPDATE_DISABLED`，粒停发）。
- 只想要粒子不要体积雾：`march_steps = 1` 或把体积雾网格隐藏。
- 画质档位：`apply_quality(tier)` 会同时调分辨率/迭代趟数/粒子数/步进次数。
- 回读接口（`read_density_image()` 等）会触发 GPU→CPU 同步，**只能用于自检**，不要每帧调用。
