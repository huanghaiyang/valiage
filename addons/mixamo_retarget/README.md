# Mixamo 动画绑定（Godot 编辑器插件）

把 **Mixamo（或任意人形骨架）的 FBX / glb 动画**自动重定向到你的角色骨架上，生成一份可直接播放的
`AnimationLibrary` 和挂好 `AnimationPlayer` 的场景。**支持增量更新**：以后新下的动作只烘焙新增/改动的那几个。

面板位置：编辑器右侧停靠栏「**Mixamo 动画绑定**」（没出现时到 项目设置 → 插件 勾选）。

---

## 使用

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① | **扫描源动画** | 列出源目录里每个 fbx 包含的动画、时长、轨道数、动作幅度；静止 take 会标为"跳过" |
| ② | **生成动画库** | 重定向到目标角色骨架 → 写 `.tres`（默认 `res://assets/animations/mixamo.tres`） |
| ③ | **生成场景** | 产出 `<角色名>_scene.tscn`（角色 + AnimationPlayer + 动画库），打开就能播 |

**换角色**：把「目标角色 .glb」和输出路径改成新角色，再点 ②③。身高/骨架不同会自动适配。

### 选项

| 选项 | 说明 |
|---|---|
| 采样帧率 | 默认 30（Mixamo 本身就是 30fps） |
| 位移缩放 | `自动（按髋高比）` / `按身高比` / `不缩放` —— 角色身高不固定时靠它对齐步幅 |
| 自动对齐朝向 | 用双脚平均方向算 yaw（单脚会带"自然外八"偏差） |
| 朝向修正° | 自动值之外再补一个角度 |
| **增量更新** | 默认开：已烘焙且**没变化**的源直接跳过；同名动画**替换**而不是重复添加 |
| 清理已删除的源 | 源文件被删掉时，把它的动画从库里移除 |

---

## 增量更新是怎么判断的

- 每个源文件的**签名 = 文件大小 + 修改时间**；
- 签名记录写在**动画库自己的 metadata**（键 `mixamo_sources`）里 → **只有一个 `.tres`，不需要额外清单文件**；
- 每次点②：
  - 源没变 → **跳过**（不重新烘焙，秒完成）；
  - 新文件 → 烘焙并**追加**；
  - 同名文件变了（重新下载/替换）→ 视为更新，**替换**该动画（先删同名再加），不会出现重复动作；
  - 库里没有清单（例如早期版本烘的库）→ 全部重建一遍，但**不会产生重名动画**，并写入清单。

## 原理与注意事项

算法：把源骨骼的**世界形变** `D = G_pose · rest⁻¹` 搬到目标骨骼自身的 rest 上（`G_tgt = D · rest_tgt`），
再换算回父空间局部值；位移按髋高比缩放、朝向自动对齐。

- 源骨架里**未被映射的中间骨骼**（如 Mixamo 的 `Spine1`）也会参与姿态计算，否则旋转会丢、动画发硬；
- Godot 的 FBX 导入器会把骨骼名改成下划线形式（`mixamorig_Hips`），映射表已兼容；
- 一个 FBX 里可能有多条动画：真实动作全部保留（命名 `<文件>/<动画>`），静止 take（约 0° 变化）自动跳过；
- **源动画必须放在 Godot 会扫描的目录**（以 `.` 开头的目录不扫描，例如 `assets/.mixamo`）；
- 某个 fbx 还没被导入时，① 会显示"加载失败（Godot 还没导入）"——在 FileSystem 里右键它 → 重新导入，再点②；
- 重定向只解决"骨骼动画"，模型自身的蒙皮权重问题（多层衣服穿模等）需要单独处理。

## 删除某条动画

- **面板**：点②生成动画库后，下方列表列出**整个库**的动画 → 选中（可 Ctrl/Shift 多选）→ 点 **「删除选中动画」**。
  删除会登记到库的清单里，**增量更新不会再把它加回来**；想恢复就取消勾选「增量更新」再点②（全量重建）。
- **手动删源文件**：删掉 `assets/mixamo/` 里对应的 fbx → 勾上「清理已删除的源」→ 点②。
- **手动改 .tres**（文本）：删掉 `_data` 里那一行 `&"动画名": SubResource("Animation_xxx"),`，
  同时删掉对应的 `[sub_resource type="Animation" id="Animation_xxx"]` 整段，保存即可。
  ⚠️ 纯文本删除不会登记 `deleted`，所以如果那个源文件之后变了，增量更新会把它烘回来。

## 运行时重定向（一份动画给所有角色用）

面板的 **④ 生成运行时场景** 会生成 `<角色名>_runtime.tscn`：角色 + 一个 `MixRetarget` 节点
（`runtime/mix_retarget_node.gd`）。它**不依赖烘焙的 .tres** —— 节点自己在场景里挂一套隐藏的 Mixamo
骨架播放动画，每帧把姿态按映射搬到角色骨架上。

```gdscript
$MixRetarget.play("Standard Walk")   # 名字 = 源文件基名（一个文件多条动画时：基名/动画名）
$MixRetarget.clip_names()            # 列出所有可用动作
$MixRetarget.stop()
```

- **换角色**：只改 `target_path`（把节点挪到别的角色下也行）→ 同一份 Mixamo 动画服务所有角色，**不用重新烘焙**；
- 位移按髋高比自动缩放、朝向自动对齐、静止 take 自动跳过（与烘焙版同一套算法）；
- 只在播放时实例化需要的那个源骨架，切换动作时替换，不会常驻所有源；
- 目标骨架的解析是**惰性**的，所以在别人脚本的 `_ready()` 里直接 `play()` 也不会踩空。

### 两种模式怎么选

| | ② 烘焙（离线） | ④ 运行时 |
|---|---|---|
| 产物 | `<角色>_mixamo.tres` | `<角色>_runtime.tscn` |
| 播放 | 普通 `AnimationPlayer`，运行时零额外开销 | `MixRetarget.play(...)`，每帧算一次姿态 |
| 换角色 | 每个角色重新点一次② | **只改 target_path** |
| 适合 | 单角色、想要最省运行时开销 | 多角色共用一套动画 |
