# 蝴蝶飞舞（Butterfly Swarm）—— 使用说明

在指定 3D 区域里随机飞舞的蝴蝶群：**多选 PNG 素材**、**按图中轴折成 V 形双翅**、**每只独立扑翼**、
内置 **Boids + 状态机 AI**，并**接入 `Weather` / `Wind`** 让风真的把蝴蝶吹偏。

> 素材：`assets/textures/活体/蝴蝶/`（20 张正面蝴蝶图，**真透明底**）
> 核心文件：`addons/butterfly_swarm/` ｜ 着色器：`assets/shaders/butterfly_wings.gdshader`
> 接口契约与全部实测结论（含踩过的坑）：`addons/butterfly_swarm/CONTRACT.md`

---

## 30 秒上手

1. **看效果**：菜单 `项目 → 工具 → 蝴蝶：打开预览场景`
   （会打开 `addons/butterfly_swarm/butterfly_swarm_demo.tscn`：地面 + 花丛 + 10 只蝴蝶，不动你的主场景）
2. **放进自己的场景**：菜单 `项目 → 工具 → 蝴蝶：注入到当前场景（自动找地面）`
   —— 自动站到玩家面前 4 米、向下打射线找地面，配好 6 张素材 / 14 只 / 6×2.6×6 米区域。可 Ctrl+Z 撤销。
3. **改素材**：选中场景里的 `ButterflySwarm` → 检查器里「素材批量添加」面板直接点按钮
   （**全部 20 张 / 选文件… / 随机 8 张 / 清空**，也能粘贴一串路径批量加），
   或用菜单 `蝴蝶：选择蝴蝶素材…` 打开多选对话框。

### ★ 任意图片素材的加入与替换（UV 是自动的，也有手动按钮）

**你不需要先跑扫描工具，也不需要那份清单。** 往 `sprites` 里塞任意 PNG 就能用：

- 裁过的 / 没裁的 / 四周透明留白宽窄不一的 —— **每张图各自算自己的不透明包围盒**，蝶体大小与折缝自动对齐；
- 白底无 alpha 的图也能处理（白色像素会被当背景忽略）；
- 换图**立刻生效**：缓存键是「路径 + 字节数 + SHA256」的**内容指纹**，内容一变自动重算，不用重启编辑器。

| 入口 | 位置 | 作用 |
| --- | --- | --- |
| 自动 | 每次 `rebuild()` | 按内容指纹为每张图算 UV 裁剪；已算过的直接命中缓存（实测 20 张首次 ~1.6 s，再重建 ~43 ms） |
| **重建 UV 裁剪** 按钮 | 检查器「素材批量添加」面板 | 清缓存 + 逐张重扫 + 写回每只蝴蝶（**不重建节点**，位置/状态不丢），并显示「N 张 ｜ 第 G 代 ｜ 耗时 ms」 |
| 菜单 | `项目 → 工具 → 蝴蝶：重建 UV 裁剪（换图后用）` | 同上（需先在场景树选中蝴蝶群） |
| 菜单 | `项目 → 工具 → 蝴蝶：重新扫描蝴蝶素材` | 重写 `sprite_manifest.json`，**并顺手重建选中群的 UV** |

> 什么时候需要点按钮？其实**基本不用**。留它是为了两种情况：① 你改了图想立刻确认结果；
> ② 怀疑裁剪不对（例如图的外圈是半透明灰边被算进了前景）时强制重算。

> 那份 `sprite_manifest.json` 现在只承担一件事：**`sprites` 为空时告诉插件"素材目录里有哪些图"**。
> 它不再参与任何一张具体贴图的裁剪计算 —— 所以它过期也不会让蝴蝶显示错。

### ★ 批量加素材（不用一张张点「添加元素」）

`Sprites` 是 `Array[Texture2D]`，Godot 默认 UI 只有一个「添加元素」按钮、**每次只能加一张** ——
20 张素材要点 20 次。所以选中 `ButterflySwarm` 后，检查器里会多出一排按钮：

| 按钮 | 作用 |
| --- | --- |
| **全部 20 张** | 把素材目录里的蝴蝶 PNG **一次全部**加进来 |
| **选文件…** | 打开文件对话框，按住 Ctrl / Shift **一次多选**若干 PNG |
| **随机 8 张** | 从素材目录随机**追加** 8 张（追加，不替换已有） |
| **清空** | 清空 `sprites`（之后退回"按清单兜底 8 张"的行为） |
| 路径输入框 + **添加** | 粘贴一串路径（`;` 或换行分隔）批量加，适合从别处拷路径 |

全部支持 **Ctrl+Z 撤销**；重复的会自动去重，非法路径静默跳过。
脚本里对应 `add_sprites_from_paths()` / `add_all_sprites_from_folder()` / `add_random_sprites()`。

> ⚠ 换了素材图片后记得点菜单 `蝴蝶：重新扫描蝴蝶素材`：清单里存的是每张图的**不透明包围盒**，
> 图换了（哪怕只是重新裁剪过）包围盒就会变，清单不更新会导致自动裁剪用错范围。
> 自检脚本会检查这一点（清单与现场重扫不一致就报红）。

## 关键参数（检查器里都能看到，改了**立刻重建**，不用运行）

| 参数 | 作用与建议 |
| --- | --- |
| `sprites`（`Array[Texture2D]`） | 可多选蝴蝶 PNG。**留空也能跑**：会自动按清单/目录兜底补 8 张 |
| `count` | 只数。12 只"有生气不吵闹"；60 只就是"蝴蝶谷"。建议 ≥ 8 才有群飞感 |
| `region_size` / `region_offset` | 区域盒子（节点本地空间，米）。**蝴蝶只在里面飞**（软回弹，不是硬墙） |
| `autofit_region` | 按地面自动抬高区域（需要场景里有碰撞体，或放一个 `butterfly_ground` 分组的空节点标地面） |
| `enabled` | 总开关：关掉整群隐藏并停止推进（不释放节点，打开即恢复） |
| `seed_value` | 随机种子。同一个种子 → 同样的初始布局与决策序列（截图对比/复现问题用） |
| `wind_influence` | 风的整体影响：0 = 无视天气风，1 = 原样，2 = 加倍（做"狂风里的蝴蝶"演示） |
| `ground_avoid` | 避地（不让蝴蝶钻进草皮/地形） |
| `debug_draw_region` | 画区域线框，肉眼确认范围（纯辅助，不影响渲染） |
| `threat_path` | 受惊源（留空自动用 `player` 分组）。靠近时蝴蝶转成 FLEE 冲刺 |
| `tuning` | 调参资源（可选）。留空用内置默认值；想复用一套手感就存成 `.tres` |

### ★ 四项"用户可自行决定"的参数（本次改进重点）

| 想决定什么 | 用哪些参数 |
| --- | --- |
| **范围** | `region_size`（三轴任意）+ `region_offset`；懒得填就用 `region_preset` 四档预设；要贴地就开 `autofit_region` |
| **素材** | `sprites` 多选；检查器「素材批量添加」面板（全部 / 选文件 / 随机 / 清空 / 粘贴路径）；菜单「蝴蝶：选择蝴蝶素材…」对话框。**注意：换了图片后要重扫清单** |
| **张翼最小/最大角度** | `dihedral_min_deg` / `dihedral_max_deg`（0~90）。这两个就是扑翼的上下限，直接决定"扇多大" |
| **数量** | `count`（0~400） |

### ★ 体积感（"蝴蝶像纸片"怎么解决）

一片零厚度平面怎么折都只是纸：正视一片均匀色、侧视一条线、掠射没有高光。本插件用三条**可独立关闭**的手段：

| 手段 | 参数（关掉它就回到纸片） | 原理 |
| --- | --- | --- |
| **弧度**（最重要） | `wing_camber = 0` | 二面角沿翼展递增 → 翅面是**曲面** → 出现连续明暗渐变 |
| **厚度外壳** | `wing_thickness = 0` | 几何生成"前层+后层+四条侧壁"的闭合薄壳 → 侧视有宽度的边、边缘吃到高光 |
| **实体身体** | `body_scale = 0` | 沿头尾的纺锤实体（颜色从素材中轴采样）→ 任何角度都有"质量" |

再加**边缘环压暗**（`rim_dark`，代替没有 AO 的立体感）与一点镜面高光。
`edge_min_facing`（默认关）可以让"侧对镜头"时自动转正一点 —— 但厚度+身体已经解决问题了，所以默认不开。

> ⚠ 厚度只能在**几何**里做：Godot 顶点阶段没有 `FRONT_FACING`，想在着色器里"按正反面往外推"会直接编译失败。

### ★ 与「合批」的关系（重要）

本仓库主场景有个可选的**合批**优化（`scripts/world/prop_merge.gd`，由 `prop_batch` 插件勾选
`allow_batch` 触发）：它会把被勾节点的**整棵子树**里所有 `MeshInstance3D` 合并成一个静态网格并
释放原件 —— 这会把蝴蝶压成一块**冻结的白片**（逐只材质失效、顶点被烘死）。

**本插件已自动免疫**：蝴蝶的 `visual` 上带 `meta["batch"] = false`，而 `prop_merge` 的契约里
正好认这个标记（排除该项）。实测：合批 72 件道具时，40 只蝴蝶全部存活并继续飞。

> 所以你现在**可以放心勾选合批**。如果你自己写了类似的网格合并逻辑，请照 `prop_merge`
> 的约定跳过 `has_meta("batch") and not get_meta("batch")` 的节点；或直接跳过
> `ButterflySwarm` 的子树（它是运行时逐帧改顶点/材质的动态物体，合批在语义上不适用）。

`ButterflyTuning` 里可调的：翼展、最大速度、扑翼频率与抖动、二面角上下限、漫游抖动、分离半径、
风拖曳、感知半径、能量消耗/回补、躲雨阈值、虹彩/逆光、贴地高度、边界带宽度、侧倾上限、
弧度/厚度/身体粗细/最小正对度/边缘压暗……

### 代码接口

```gdscript
var swarm := ButterflySwarm.new()
swarm.count = 20
swarm.region_size = Vector3(10, 3, 10)
swarm.set_sprite_textures([tex_a, tex_b, tex_c])   # ★ 用这个方法，别直接给 sprites 赋无类型数组
add_child(swarm)

swarm.set_active(false)        # 整群停下（隐藏 + 不推进）
swarm.respawn_all()            # 重新撒一遍
swarm.wind_now()               # {"dir": Vector2(世界XZ), "strength", "gust", "turbulence", "speed", "source"}
swarm.weather_now()            # {"kind", "name", "wind", "gust", "rain", "cloud", "source"}
swarm.stats()                  # 只读快照：live / sprites / speed_avg / state_histogram / 高度范围…
```

> ⚠ `sprites` 是 `Array[Texture2D]`，所以 `swarm.sprites = [a, b]`（无类型字面量）会报类型错。
> 用 `set_sprite_textures()` / `add_sprite_textures()`，它们接受任意 Array 并自动过滤。

## AI 行为逻辑（`butterfly.gd`）

**状态机**（能量与威胁驱动，不是纯随机）：

| 状态 | 触发 |
| --- | --- |
| `CRUISE` | 默认：漫游方向 + 噪声，自由巡飞 |
| `SEEK` | 附近有 `butterfly_target` / `flower` 分组的目标（蜜源） |
| `COURT` | 与随机同伴配对绕飞 |
| `BASK` | 能量低于 `rest_energy` → 落到花/叶上晒翅回能 |
| `SHELTER` | 天气恶劣（`wind ≥ shelter_wind` 或 `rain ≥ shelter_rain`）→ 下沉到背风低处 |
| `FLEE` | 威胁（玩家）在 4 米内 → 朝反方向冲刺 + 拔高 |
| `DRINK` | 汲水/停留（与 BASK 同类，落脚点在目标处） |

**转向力**：漫游（低频噪声）+ 趋目标 + 同群分离 + **风的拖曳** + 边界软回弹 + 避地。
**扑翼**：二面角按 `flap_hz` 正弦摆动，**每只频率与相位都不同**（整群不会像机器人整齐扇翅）。

**风怎么进来**（`ButterflySwarm.wind_now()`）：优先读 `Wind` autoload 的 `cur_*`（那才是草/植被实际用的那份）
→ 退回 `Weather` 的 `wind` / `wind_dir` / `wind_gust` / `wind_turbulence` / `wind_speed`
→ 都没有时用"微风"常量兜底（保证蝴蝶永远有风可用，不会静止死）。
风影响三处：① 直接拖曳速度（被吹偏）② 垂直侧向抖动力（吹得歪歪扭扭）③ 顺风省力/逆风补推力。
天气还影响：大风大雨转 `SHELTER`、雨里飞得慢且翅膀更暗更不透、阴雨天整体压暗偏冷。

## 「居中折叠」是怎么做的（核心）

素材是**正面展开的蝴蝶图**（`x` = 左翅→右翅），直接贴平面就是一块纸片。做法：

1. **自动裁剪**：逐像素量出每张图的**不透明包围盒**，只贴这一块。
   实测 20 张图的包围盒占比差异很大（宽 0.74~0.90、高 0.74~0.95），不裁的话每只大小能差 22%。
2. **折叠轴 = 包围盒的水平中心**（不是全图中心）：
   实测全图中心与真实蝶身最多差 4% 全宽（蝶身横轴 0.4621），用全图中心会让那张图的蝶身偏离折缝。
3. **折成 V**：在顶点着色器里绕**体轴（局部 +Z）**把两翅各转 `±dihedral`，
   翅尖一起抬向 +Y，形成「书脊朝下、双翅上举的 V」。
   *为什么是 +Z 而不是竖直轴 +Y*：绕 +Y 会把翅面转出所在平面，**侧视时两翅正好侧对相机**，
   蝴蝶退化成一条极窄的竖条（真机实测出过"竖线蝶"）。
4. **逐帧扑翼**：`dihedral` 由每只自己的相位驱动；大风时下限抬高（翅膀被吹得合不拢）。

## 素材清单（`sprite_manifest.json`）

生成方式：菜单 `项目 → 工具 → 蝴蝶：重新扫描蝴蝶素材`，或无头跑
`addons/butterfly_swarm/tools/analyze_butterflies.gd`。

清单存每张图的 `w/h/bbox/body_x`，用途：① 没配 `sprites` 时兜底 ② 编辑器多选对话框的条目来源。
**换了素材记得重扫一次**（逐像素解码 20 张约 1~3 秒，所以做成手动而不是自动）。

> ⚠ 清单的 bbox 来自**原始 PNG 字节**，不是 `Texture2D.get_image()`：
> 实测导入后的贴图是 1188×804（导入器补了 2px 边）且**四周全不透明**，用它算 bbox 会退化成整图、
> 裁剪直接失效。而 GPU 采样的是导入贴图，两者尺寸只差补边、比例几乎相同，所以用原始尺寸算 UV 是对的。

## 排障（都是本项目真踩过的，按此顺序查）

| 现象 | 原因 / 处理 |
| --- | --- |
| 一只都看不见 | ① 没配素材？看检查器警告 ② `count=0` ③ 着色器缺失（会 push_warning）④ 区域埋进地形（勾 `debug_draw_region` 看盒子） |
| 蝴蝶是"竖线"/一片纸 | 折轴被改回 +Y 了（见上）；或相机正好在翅面平面内（换个视角即可） |
| 颜色发紫、不像素材 | 虹彩被写进了 `ALBEDO`。它**只能加在 `EMISSION`**（`iridescence=0` 可完全关掉） |
| 蝴蝶飞出区域 | 边界的越界力必须**随超出量增长**（第一版固定力在阵风下实测外溢 0.39 m） |
| 树内却报告"没有天气系统" | 裸用 `get_tree()` 在节点刚入树时会拿到 null；统一走 `scene_tree()` / `scene_root()` |
| 每帧刷 `Node not inside tree` | 树外调 `advance()` 时 `look_at()` 失败；`Butterfly` 里有树外手工基回退 |
| 换天气蝴蝶没反应 | `wind_influence` 是不是 0；或 `Weather`/`Wind` autoload 被改名 |
